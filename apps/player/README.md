# MUSIC PLAYER

Appsの末尾。SDカード上のファイルを1つ選んで鳴らす。`fs.pickFile` の最初の利用者で、
`pocket.audio.player` の既存経路（WAV / Opus / MP3）をそのまま使う。

| キー | 動作 |
| --- | --- |
| ENTER | 再生 / 一時停止。終わっていたら同じ曲を頭から |
| RIGHT | 別のファイルを選ぶ |
| ESC | 終了（**再生も止まる**。理由は下） |

## 許可を先に訊かない

`pickFile` を**先に呼び**、`PERMISSION_DENIED` が返ってきたときだけ `requestFolder`
を出す。許可の有無を訊く問い合わせはAPIに無い（意図的で、`sd_path.h` が
「許可されていないアプリにカードの有無を教えない」ためにエラーの順序まで決めている）ので、
**拒否がそのまま「許可がまだ無い」の唯一の合図**になる。毎回フォルダー画面を出すと、
1セッション中に一度答えた人にもう一度同じ質問をすることになる。

人が断ったときは `null` が返る。これは失敗ではないので、アプリは落ちずにその旨を出して待つ。

## 抜けると止まる

**ESCで戻ると再生は止まる。** バグではなく、いまの構造そのものである:

- JSセッションは同時に1つで、前景アプリを抜けるとセッションは破棄される。
- 供給は `pocket_av_pump()` → `pocket_fs` の読み出しで、**そのセッションのタスクのもの**。
  `pocket_av_reset()` がセッション終了でリングもデコーダーも落とす。
- MP3は `seekable:false` なので、仮に別セッションへ渡しても**位置を持って引き継げない**。
  引き継ぎは必ず頭からの鳴り直しになる。

ホーム画面で鳴らし続けるには、プレイヤーが**overlayセッション側**に居る必要がある
（`docs/common-api.md` 3.1）。そのためにネイティブ側で足りていないものは
`docs/player-overlay.md` に列挙してある。

## 長さと位置

MP3の `info().durationMs` は再生が終わるまで `null` で、終わってから実出力時間を返す。
画面が「LENGTH UNKNOWN」と出すのはそのためで、0msを長さのように見せない。
一時停止からの再開は先頭から復号してbit reservoirを復元するので、
**長い曲の後半ほど再開が遅い**。これはフォーマットの性質でこのアプリの都合ではないが、
待ちが出るのは状態行なので、そこに出る。

## カードのクロック

初回の実機試験でSDからの再生が**ぶつ切りになった**。原因は `sd_media.c` が
識別用の400 kHzを転送クロックのまま使っていたことで、2,048バイトの補充1回に
約41 msかかり、33 msのフレームに収まらなかった。20 MHzへ上げて解消している。

**20 MHzは「このドライバがマウントを通す上限」であって「この配線が運べる上限」ではない。**
30 MHzと40 MHzはどちらも `sdmmc_enable_hs_mode_and_check: send_csd returned 0x108`
で落ちるが、`sdmmc_init.c` はHS切り替え（step 156）をホストのクロック変更（step 178）
より**先**に行うので、**その30/40 MHzは一度もバスに出ていない**。落ちているのは
CMD6のHS切り替え**直後のCMD9**で、しかも400 kHzで、である。カード側はCMD6を
受け付けているのでHSモードには対応しており、これはこのカードのSPIモードでの
振る舞いであってこの基板の信号品質ではない。**別のカードなら通る可能性がある。**
詳細と、25 MHzへ上げる仕様内の抜け道は `sd_media.c` のコメント。

## まだ測っていないこと

**カードの読み出し自体は一度も計時していない。** 20 MHzで音は繋がったが、
それは「間に合った」であって「どれだけ余裕があるか」ではない。
より高いビットレート・断片化したファイル・描画負荷の高い背景との同居は未確認。
`sd_media.h` が `SD_MAX_OPEN_FILES` の変更を保留した理由もこの測定待ちである。

`extensions` は `.mp3` `.wav` `.pok` の3つ。`.pok` はこのプロジェクトのOpusコンテナ
（`apps/opusplay` 参照）。**Ogg入りの `.opus` は復号できない**ので候補に出さない——
開けないファイルを並べるフィルターは、狭いフィルターより悪い。
形式を決めるのは拡張子ではなくマジック（`pocket_av.c` の `source_parse`）なので、
名前だけ合っているファイルはopenで断られる。
