# Cardputer ADV デザインシステム仕様 v0.2

状態: 一部実装済みの仕様。2026-09-13。数値のうち「予算」「目標」は未実測であり、達成済みの値ではない。
v0.2の必須要件と追加機能は[コンポーネント合成・キャッシュ・モーダル仕様](design-composition.md)に定める。該当事項は同書を優先する。
対象は240×135、PSRAMなしのCardputer ADV。QuickJSから直接利用する描画APIと薄いJS部品ライブラリを定義する。
ペットアプリでの具体化は[ペット適用仕様](design-system-pet.md)を参照。
色・部品・演出・モーダルの制作時の記述形式は[デザイン定義スキーマ](design-schema.md)を参照。
時計・電源・通知の状態管理と省起床の契約は[システムランタイム仕様](system-runtime.md)に分離する。DSはその状態を表示する利用側であり、購読・タイマー・時計の実装を重複して持たない。

## 1. 目的と境界

優先順位は省メモリ性、描画負荷、入力応答、装飾機能の順とする。
PocketJSのUI木・スタイル・Taffyレイアウトへの依存を置き換える。QuickJSのVM改造、入力、保存、音声、通信のサービスは別の責務として残す。
移行対象のサービスまで一括削除することを本仕様の前提にしない。

部品は描画命令を生成するJS関数とし、ネイティブに部品木を持たせない。
部品の配置情報は矩形の2点を基本とする。ただし描画には色・文字・画像参照・クリップも必要であり、「2点だけで描画状態の全情報が足りる」とはしない。
padding、flex、grid、内容に応じた親サイズの自動計算、制約の反復解決は行わない。
必要な余白や整列はJSヘルパーが画面構築時・状態変更時に座標へ解決する。

既存実装では`main/hal/board.h`に240×8×2 = 3,840 Bの共用転送バッファがある。
`main/app_session.c`の`present_frame()`は更新領域が存在すると全17帯を描く。
新方式ではこのバッファを共有し、変更のある帯だけ再合成・転送する。
フル画面のRGB565バッファ64,800 Bや、部品ごとの暗黙のピクセルバッファは持たない。明示的な命令キャッシュを必須とし、pixel cacheと効果用画像は別途指定した追加予算に限る。

## 3. 座標と描画命令

- 矩形は半開区間`[x0,x1) × [y0,y1)`。保存座標は符号付き16 bit、計算は32 bit以上で行う。
- JSの有限数を最近接整数へ丸め、ちょうど半分は0から遠い側へ丸める。範囲外、NaN、無限値、反転矩形は拒否する。幅または高さ0は描画なし。
- 配列順が重なり順。クリップは矩形の交差で、描画先矩形とは独立する。
- 構築時のclip/offsetスタックは合計深さ8。命令には解決済みの座標とclipを保存し、親参照を持たせない。`end()`時にスタックが釣り合っていなければ失敗する。
- 平行移動アニメーションは描画対象だけを動かす。クリップを動かす場合は明示的に更新する。

| プリミティブ | v0.1の契約 |
| --- | --- |
| rect | 単色矩形、命令単位の不透明度 |
| strokeRect | 内側1〜2 pxの枠 |
| roundRect | 半径最大8、走査行区間で描画 |
| gradient | 水平または垂直の2色、角丸と併用可 |
| text | 1行、明示矩形内でクリップ、文字送り可 |
| image | Flash資源、切り出し、最近傍の1倍・2倍・1/2倍 |
| pet | 既存PPT2を行単位で展開、1倍・1/2倍、表情指定 |

基本描画経路はblur、任意パス、任意回転、任意倍率、複数色停止点、任意角度グラデーションを扱わない。v0.2のblur・変形・平面投影は別途定義したBETTERの効果経路で追加する。
例外として静止背景を縮小保存するすりガラスモーダルを任意拡張とする。汎用blurとは分け、追加2/6 KiBの予算・失敗時の単色fallbackを[スキーマ仕様](design-schema.md)で定める。1/8縮小の画素フィルタと画質診断は実装済み、実アプリのcapture/attachは未実装。基本16 KiB予算には含めない。
命令の不透明度と、部品内部を合成した結果へ1回適用するグループ不透明度を区別する。v0.2では両方を必須とし、後者は全画面バッファではなく小さい行タイルで処理する。

## 4. グラデーションと合成

グラデーションの基準はクリップ前の元矩形。長さLに対し位置iの補間係数は`i / max(1,L-1)`、L=1は先頭色とする。
8 bitの各色チャンネルを整数丸めで補間する。垂直は行ごとに1色、水平は最大240色・480 Bの共用ランプを利用できる。
大きなグラデーション画像を保持しない。色補間は符号化されたRGB値上で行い、線形光合成はv0.1では行わない。

RGB565の階調対策として固定4×4 Bayerディザを任意指定できる。
行列は`[0,8,2,10; 12,4,14,6; 3,11,1,9; 15,7,13,5]`。
画面座標に固定し、時刻やdirty範囲で位相を変えない。
8 bit値c、出力最大値m=31または63について、`q=floor(c*m/255)`、`r=c*m-255*q`とし、`32*r > (2*B+1)*255`ならqを1増やしてmで制限する。

透明合成は既存`main/scene/render_accel.c`のスカラー式を基準とする。
coverageとglobal alphaは`(coverage*alpha+127)/255`、RGB565の背景をbit複製で8 bit化し、各成分を`(src*a+dst*(255-a)+127)/255`で合成する。
ディザなしでは従来通りRGB565へ切り詰め、ディザありでは合成後に上記量子化を適用する。a=0は背景を一切変更しない。
PIE経路は対応するスカラー経路と全画素一致させる。既存の加速範囲外はスカラーへ戻し、全処理が加速されるとは仮定しない。

## 5. 常駐メモリ予算

以下はCardputerプロファイルの設計上限。実装時に構造体サイズ、アラインメント、実際の割当量を検証する。

| 領域 | 予算 B |
| --- | ---: |
| 描画命令 96件 × 32 B × 2バンク | 6,144 |
| UTF-8文字領域 1,024 B × 2バンク | 2,048 |
| アニメーション 8件 × 64 B × 2バンク | 1,024 |
| 任意の字形キャッシュ、タグ込み | 1,024 |
| 共用描画scratch | 512 |
| clipスタック・資源記述・世代・damage・統計など管理領域 | 1,024 |
| 既存の共用LCD転送バッファ | 3,840 |
| 合計 | 15,616 |
| 16 KiBまでの未配分余裕 | 768 |

ネイティブUIの上限目標は既存転送バッファ込み16 KiB。2バンクは命令と文字の状態を保持するもので、ピクセルの二重バッファではない。
v0.2のtemplate/instance metadataはこの基本枠内で再配分する必要があり、収容は未検証。RAM cache本体はcacheBytesで最大4 KiBを明示追加する。基本枠・cache・backdrop・effectの同時ピークを合算し、16 KiBに収まったと誤記しない。
アプリ枠は命令80・文字896 B・アニメーション6件、システム通知枠は命令16・文字128 B・アニメーション2件とする。
初期化の単一確保は最大3,072 Bとし、途中失敗時は取得済み領域を戻す。描画・差分検出・アニメーションの各フレームではヒープ確保しない。
scratchのランプ・マスク・PPT2行は同時利用を避け、必要なら順に再計算する。隠れた別scratchを増設しない。

この表にQuickJS、アプリのJS状態、OSの予約スタック、保存・通信サービス、Flash資源は含まない。
ペットでのDS用JSヒープ増分8 KiB以下、描画呼び出しの追加スタック1 KiB以下を別目標とし、装置全体のピークも必ず報告する。
「初期化後の最大追加確保」と「UI全体の常駐量」は別に測る。従来uibudgetの小さい追加確保値を総量として比較しない。

命令32 Bの内訳は種別・フラグ・不透明度等4 B、描画矩形8 B、clip矩形8 B、種別別payload12 B。
文字payloadは例えばoffset2、length1、capacity1、font1、reveal1、flags2、RGBA4 Bで収める。文字列自体は別の固定文字領域に置く。
可変長の部品レコード、スロット管理表、命令ごとのヒープオブジェクトは設けない。
v0.2の共有template/instanceには件数上限付きの固定metadataを認める。これは部品ごとの可変長heapや汎用レイアウト木を再導入するものではない。

## 6. 文字と資源の寿命

文字はUTF-8をネイティブ領域へコピーする。1命令は最大128 Bで、作成時に更新用capacityを予約する。
`setText`は予約内で上書きし、超過時は明示エラー。フレームごとの文字列結合を避けるため、整数値の直接更新も用意する。
不正UTF-8は拒否する。文字送りはUnicode scalarの境界で切り、書記素クラスタ、双方向組版、複雑なシェーピングは保証しない。
日本語のFlash字形を直接参照できるようにし、文字追加のたびに全文字アトラスを再生成しない。
文字の実バイト列も差分判定し、同じoffsetで内容が変わった場合を見落とさない。

Flash資源の記述は最大16件、セッション中は追記のみで番号を再利用しない。上記管理領域に含める。
登録はホストだけが行い、APP/SYSTEMの所有レイヤーを固定する。構築中・提出中の登録はBUSY。
descriptorをコピーし、providerのctx・Flash内容はcore初期化による借用終了まで不変かつ有効に保つ。
個別の削除・解放は行わないため、表示済み・構築・提出のいずれの参照も提出破棄で失効しない。
資源IDはプロセス寿命の単調32 bit番号とし、core再初期化でも戻さない。枯渇時はLIMIT。
画像追加とframe変更で所有者・番号・variant/frame上限を検証し、行読出しでは提出IDと座標・出力容量に対応するcountも検証する。
描画中にSD・ネットワークへアクセスしない。動的画像の読み込み・保持は別途予算化するまで未対応とする。
PPT2は既存の7,601 BのFlashデータと128 Bの行展開を利用し、8 KiBの全身テクスチャを作らない。

## 7. 更新の公開と失敗時の契約

`begin('replace')`は画面を再構築し、`begin('patch')`は現在の論理状態をコピーして一部を変更する。
`end()`は検証済み状態を提出し、`abort()`は構築を捨てる。
表示済みバンクと構築/提出バンクの2つだけを持つ。提出中の次の更新はBUSYとし、JS側は最新のアプリ状態を保持して再試行する。第3バンクや無制限キューは作らない。
システム通知も同じ公開手順に従い、構築中のバンクを横から変更しない。

命令参照は配列index7 bitと世代25 bitを持つ32 bit値とする。
replaceの開始時に世代を消費し、abortや失敗でも再利用しない。成功した世代だけ有効化する。
patchでは参照と命令数を維持する。追加・削除・並べ替えはreplaceで行い、patchでの追加はINVALIDとする。
世代とトランザクションIDは全コアで共有するプロセス寿命の単調カウンタから発行する。
セッション再初期化でもカウンタを戻さない。世代25 bitまたはトランザクション32 bitの枯渇では該当beginをLIMITとし、プロセス再起動まで再利用しない。
これは「枯渇時にセッション再作成」で番号を戻す旧案を修正したもの。古い参照の復活を防ぐ。
setterは呼出元レイヤー、トランザクションID、世代、index、命令種別を検証する。
別レイヤーや古いトランザクションの呼出しはSTALEで拒否し、正しい所有者の構築をpoison/abortしない。

構築途中でJS例外・VM yield・容量超過が起きても未完成画面を公開しない。
構築エラーはそのトランザクションを失敗状態にし、abortまで提出できない。
提出状態を表示済み状態へ昇格するのは必要な帯をすべて転送した後。転送失敗は旧基準を保持して次回全面再送する。
LCD上で複数帯が一瞬に切り替わる保証はしない。変化画素が0なら転送なしでメタデータのみ確定できる。
描画中はJSを呼ばず、ISRからもJSを呼ばない。

ホストは提出IDで旧/新の命令を1件ずつ呼出側バッファへ読み出す。内部バンクへのポインタは公開しない。
全帯成功のackと提出破棄にも同じIDを要求し、以前の提出に対する遅延ackを拒否する。
転送途中の失敗を記録した後は、提出を破棄しても全面再送フラグを残す。破棄するホストは次の提出を必ず予定する。
起動直後は不透明な黒を空のAPP基準とし、最初のAPP構築前でもSYSTEM通知を提出できる。APPのreplaceには引き続き明示背景が必要。

## 8. 部分描画

高さ8の全幅帯17本を32 bitのdamageビット集合で管理する。最後の帯は7行。
変更した命令の旧・新それぞれの描画矩形とclipと画面の交差から対象帯を求める。非表示化も旧範囲を消す。
対象帯では背景から順に、帯と交差する全命令を再合成する。変更した命令だけ上書きして残像を作らない。
移動、半透明、角丸、文字更新、吹き出し消去、システム通知に同じ規則を適用する。
replaceは全面damageを許す。patchとアニメーションでは無関係の帯を転送しない。
最初は最大96×17の単純走査とし、空間索引の常駐メモリを追加しない。
転送バッファは転送完了まで再利用しない。変更なしなら再合成もLCD転送も0。

現在の初期レンダラは矩形と命令単位alphaを扱う。背景変更・replace・転送失敗後は全面、patchでは変更命令の旧/新範囲のみを対象とする。
未対応の命令がある提出は、最初のLCD転送前にUNSUPPORTEDとして保留する。文字・画像等の画素生成が完成するまで、APIへの保存成功を描画対応済みとはしない。

## 9. アニメーション

ネイティブの固定トラックが時刻から値を計算する。JSは開始・変更・停止時だけ呼び出し、フレームごとのclosureやPromiseを作らない。
1トラックは連続した命令範囲と、translate、opacity、color、revealのいずれかを対象にする。
同じ命令・同じ属性に複数トラックを重ねない。手動更新前に現在値へ停止・焼き込みする。
補間はQ16.16等の固定小数点と64 bit中間演算。丸め規則は座標規則に合わせる。
linear、easeOutCubic、easeInOutCubic、stepを用意し、有限回・loop・pingpongを明示する。
遅延時は現在時刻の値へ飛び、失われたフレームを連続実行しない。

表示済みのサンプル時刻と次のサンプル時刻から旧・新範囲を算出する。
描画時に命令の一時値を評価し、構築中でも表示バンクを書き換えない。
終端値は次のpatch開始時に命令へ焼き込み、終了トラックを回収する。完了通知はトラックごとの固定ビットで次の安全なJS実行機会へ渡す。
提出時刻を開始時刻とし、表示待ち時間も経過時間に含める。
reduceMotionでは装飾的補間を終端へ進める。非表示時は描画のために起床せず、復帰時に時刻から再評価する。

描画上限は30 Hz。常時30 Hzのタイマーを必須にせず、次に表示値が変わる期限を使う。
ペットのステータス2 Hz、表情最大10 Hz、bob 1 Hz、文字送り70 msは別の期限として扱う。
これはJSからホストに制御が戻った時の実行モデルである。VM L2c等が未完成の段階で、長時間JSやnative呼び出し中の描画継続を保証しない。

## 10. APIの最小面

2026-09-14: 実装済みC利用窓口とowner境界は[利用API v0.3](design-api.md)に再構成した。
以下はJS側を含む目標語彙。利用可能な能力は`ds_view_features`を参照する。

API名は提案であり、現時点で利用可能なAPIではない。

| 操作 | 契約 |
| --- | --- |
| begin / end / abort | 上記の更新単位。入れ子不可 |
| background | 不透明な画面背景を必須指定 |
| rect / strokeRect / roundRect / gradient / text / image / pet | 明示座標で作成し参照を返す |
| pushClip / pushOffset / pop | 構築時だけ有効な座標解決 |
| setRect / setClip / setColor / setText / setInteger / setReveal / setPet / setVisible | patch内で種別に合う属性を変更 |
| animate / stop | 固定トラックを開始、現在値へ停止 |
| limits / stats | 実際に強制する上限と測定値。毎フレームの取得を要しない |

エラーはINVALID_ARGUMENT、LIMIT_EXCEEDED、OUT_OF_MEMORY、STALE_REFERENCE、BUSY、UNSUPPORTEDを区別する。
容量不足をpanicや再起動に変えない。直前の正常画面を維持し、QuickJS自体のOOM時にはホスト側の固定エラー表示へ戻れること。
セッション終了時はトラック・構築状態・参照・資源借用を破棄する。入力購読等は既存サービスの寿命管理を利用する。

## 11. 受け入れ条件

以下の時間と容量は検証すべき目標である。SPI、JS、ネイティブ処理を分離し、総フレーム時間も併記する。

| ケース | 条件 / 目標 |
| --- | --- |
| 静止10秒 | paint 0、画素転送0、UI用の周期JS呼び出し0 |
| バー、まばたき、bob | 旧・新範囲に該当する帯だけ転送 |
| 部分描画 | 同じ状態の全面スカラー描画と全画素一致 |
| ペット通常画面 | ネイティブ評価・差分・合成 p95 ≤4 ms、最大8 ms |
| 96命令の負荷画面 | 同処理 p95 ≤8 ms、最大16 ms |
| ペット入力応答 | 入力から表示 p95 ≤50 ms。VM内滞留を別記 |
| nativeアニメーション60秒 | 描画系のヒープ確保0 |
