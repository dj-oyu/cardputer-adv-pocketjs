> **2026-09-09 の状況。** 下の 2 件はどちらも着手済みで、ホスト側の証明は通っています。
> **実機の数字はまだありません**（ボードは 1 台で、オーナーが持っています）。
>
> - **1. `shade` の `floorf` 2 本** — 済み。ただし提案された「引数が非負だからキャスト」
>   ではなく、前提の要らない `ifloor`/`iceil` にしました。理由と総当たりの証明は
>   `docs/pie-simd.md` §3.12、テストは `tools/test_flower_floor.c`。
>   `flower_prepare` の 4 本（`floorf` 2 + `ceilf` 2）も同じ助数詞で消えています —
>   「部品ごとに 1 回だから対象外」でしたが、最大の種で 224 本/フレームあり、
>   同じ 1 行の助数詞で消えるので分ける理由がありませんでした。
>   スイッチは `FLOWER_NO_IFLOOR`。
> - **2. `bell_hit`** — `1.0f/a` が**ピクセルに依存していませんでした**。`a` は

>   除算 4.5〜5.4 本が消えます。詳細と数え方は `docs/pie-simd.md` §3.11。
>   スイッチは `FLOWER_NO_BAND_INVA`（巻き上げ全部）と `FLOWER_NO_BAND_DOTS`
>   （30 個の積和だけ）の 2 本。**別々にしてあるのは、前者の商が `__divsf3` の
>   値段そのものになるからです。**
>

> calla で `bell` **9.05-9.55 → 7.74-8.20 ms**（1,303 → 1,107 cy/visit、**-1.33 ms/frame**）。

## 1. `shade` の `floorf` 2本

### どこ

`main/scene/flower.c`、`shade()` の `material==CHECKER` 分岐、1行に2本：

```c
int tile=(int)floorf((longitudinal+1)*4)+(int)floorf((transverse+1)*5);
```

（`flower_prepare` の中にも `floorf` が2本あるが、あれは**部品ごとに1回**で
毎フレーム数千回ではないので対象外。触る価値がない。）

### なぜ消せる**はず**なのか

`floorf` は soft-float ABI ではライブラリ呼び出しになる（`-mlongcalls` で
`l32r`+`callx8` に化けるので、ソースを読んでも呼び出しに見えない。
`docs/pie-simd.md` §3.7）。一方 C の `(int)` キャストは**ゼロ方向への切り捨て**
で、これは引数が非負のときに限り `floorf` と一致する。

引数が非負である根拠は構造的で、値の観察ではない：

- `longitudinal` と `transverse` はどちらも `DIVR(dot(local,p->axis[k]),
  p->inv_radius[k], p->radius[k])` で作られる、部品ローカルの正規化座標。
- 表面上では絶対値が 1 を超えない。したがって `longitudinal+1 >= 0`、
  `transverse+1 >= 0`。
- `*4` と `*5` は正の定数なので符号を変えない。

**だから作業の本体は編集ではなく証明の方**である。1行の置き換えは5分で、
残り全部が「本当に全種・全ポーズで1画素も変わらないか」の確認になる。

### 何を検査すればいいか

- `CHECKER` を使う種だけでいい。まず `grep -n CHECKER main/scene/flower_species.c`
  で対象種を絞る。使っていない種を回しても何も証明していないことになる。
- 検査は**全種 × 60ポーズ**の全画素比較。`tools/test_flower.c` が既に
  60ポーズを回しており、`hush_grain()` でグレインのフレーム依存を止めた上で
  `flower_draw` の出力を丸ごと `memcmp` する枠組みがそこにある。同じ形で
  `floorf` 版と `(int)` 版の2バイナリを作り、突き合わせるのが最短。
- 境界に注意：`longitudinal` がちょうど `-1` になる画素があると
  `(longitudinal+1)*4` が `-0.0f` になり得る。`floorf(-0.0f)` も `(int)(-0.0f)`
  も 0 なので一致するが、**丸め誤差でわずかに負に振れた場合**は
  `floorf` が `-1`、キャストが `0` を返して `tile` の偶奇が反転し、市松模様が
  1画素分だけ入れ替わる。ここが唯一の壊れ方なので、証明はここを見ること。
  「全画素一致した」を言うためには、この画素が検査に含まれていることを
  先に確かめる必要がある。**当たらない検査は失敗しないという意味で通る。**

### 見込み

**測っていない。** `floorf` の呼び出しコストも `CHECKER` 画素の頻度も、
実機のカウンタで測った数字を持っていない。着手する人は**先に測ること**。
`CHECKER` は一部の種の一部の材質でしかないので、削っても全体では動かない
可能性が十分にある。このプロジェクトには推定1.2msが実測25.6msだった例が
あるので、順番を逆にしない。

## 2. `bell_hit` のコスト

こちらは**測ってある**が、まだ何も手を付けていない。

### 実測値

- **1visit あたり 1,128〜1,400 サイクル。**
- **1フレームあたり 1,474〜2,761 visits。** 積で 7.9〜15.5 ms。
  30fps の予算が 33 ms なので、これは FLOWER シーンで最大の単一項目。
- 幅があるのは種による。部品数が3倍違うので、visit 数も同じだけ振れる。

### 二重計上の罠（重要）

**`bell:sqrt` は `bell` の中に入れ子になっている。** ログの `SPLIT` 行は
両方を出すが、`bell` の 1,128〜1,400 は `bell:sqrt` を**含んだ**数字なので、
足してはいけない。過去にこの入れ子を見落として「計器が黙った」形の誤診を
1件やっている（`docs/pie-simd.md` §3.10 の四つの形のひとつ）。

`sqrtf` は実測 **174 サイクル**。1 visit で最大6回（緯度帯ごとに1回）走る
ので、`bell` の 1,128〜1,400 のうち最大 1,044 がこれ、という上限が引ける。
ただし判別式が負の帯では `continue` するので、6回全部走る visit は多くない。
**実際の平均回数は測っていない。** ここは着手前に測る価値がある唯一の数字だと思う。

### すでに効いている最適化（もう一度やらないこと）

- **`bell_reject` が visit の 43.6% を、六帯の walk に入る前に落としている。**
  外接円柱を高さで打ち切ったもの。取りこぼしゼロは
  `tools/test_bell_reject.c` が全帯 walk と突き合わせて確認済み。
  ここを更に締めるなら `bell_miss_disc` / `bell_miss_height` /
  `bell_miss_depth` / `bell_miss_clip` の内訳カウンタが既にあるので、
  どの棄却理由に寄せるかはそれを見てから決められる。
- **帯の境界（`bell_lo` / `bell_hi`）と直線の係数（`bell_slopes` /
  `bell_offsets`）は `flower_prepare` に巻き上げ済み。** かつては
  `bell_hit` の中で `2.0f*band/LAT` の除算を2本、2,000 visits 分やっていた。
  `FLOWER_NO_BAND_HOIST` を定義すると昔の形に戻せるので、効果の再測定は可能。
- **2根は除算を共有している**（`inva=1.0f/a` を1回作って両根に掛ける）。
  `FLOWER_DIV_EXACT` で共有前の形に戻せる。
- 法線計算の3本の除算は `DIVR` で逆数が使えるときは逆数を使う。しかも
  **受理された visit でしか走らない**ので、visit あたりのコストにはほとんど
  効かない。

### 残っている方向（どれも未検証）

- **帯の数を6から減らす。** `FLOWER_BELL_BANDS`。コストはほぼ帯数に比例する
  はずだが、鐘の輪郭が折れ線で近似されるので**見た目が変わる**。
  「見た目が変わらないこと」を条件にできないので、これはオーナー判断の項目。
- **判別式の符号だけで早期に帯を捨てる。** いまも `disc<0` で `continue`
  しているが、`sqrtf` の**前**であって `a`/`b`/`c` の計算の後。
  帯の半径範囲から `disc<0` が確定する帯を先に落とせる余地があるかもしれない。
- **PIE 化。** 六帯は独立なのでベクトル化の形はしているが、
  `sqrtf` がライブラリ呼び出しである以上そこが直列に残る。
  `docs/pie-simd.md` と `tools/pie/` の3層（`stalls.py` /
  `test_kernels.py` / `run_models.py`）を通すこと。

## 全体に効く注意

- **命令キャッシュのアラインメントで、同じカーネルがビルド間で15%動く。**
  それ未満の差を主張するなら同一バイナリでの比較が要る。
  ビルドをまたいだ差分は根拠にならない。
- **1つのバイナリに2つの変更を入れない。** 今日これで偽の 7ms の退行を
  1件作っている（他セッションの未コミット作業を巻き込んだバイナリを
  計測に出した）。
- ホスト側の検査は `main/` のパスを直書きしているので、ファイルを動かす前に
  `grep -rn "main/" tools/` で参照元を洗うこと。
