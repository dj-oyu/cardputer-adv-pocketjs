モデル・頂点座標列・テクスチャは埋め込まない。少数の寸法から楕円体と開口した円錐帯を実行時に生成し、光線との交点を解析的に求める。カラーは曲面の切り取り条件で非対称にする。植物学的に厳密な再現ではなく、小画面で特徴が伝わる関数アート。
旧メッシュ比較方式は現在の実装にはない。crystal は非表示の検証用種として残る。

## 森の光と雨

描画順は森林背景 → 花 → 雨滴 → 既存XMB。

[Horizon Forbidden West の世界表現](https://blog.playstation.com/2021/11/22/horizon-forbidden-west-an-authentic-world/)と[Guerrilla の大気表現資料](https://www.guerrilla-games.com/read/nubis-evolved)を参考に、等間隔の明るい斜線を避け、暖色の広い散乱光、青緑の霞、薄い遠景の幹、手前の草・シダを組み合わせる。AAAの体積描画技術を移植するものではない。

garden.c は行ごとの整数演算で近似する。光の密度は64pxと32pxの2層のValue Noiseを3:1で合成し、滑らかな低周波ノイズで光の中心も少し歪める。格子値は整数ハッシュから生成し、Q8 smoothstepで補間する。格子端の値は行内の自動変数へ保持し、画素ごとの再計算を避ける。LUT・画像・頂点配列はない。

草木は区画内の位置、高さ、幅、傾き、葉の間隔をハッシュで決め、密度ノイズで群生と空白を作る。近い草は共通の連続ノイズから風を受ける。花の交換時に既存の花選択用乱数を配置seedとして渡し、幹・樹冠・草木も再配置する。交換の間は配置と形を固定する。独立した常駐乱数状態は追加しない。配置は花が消えるフレームで即時交換し、森林全体のクロスフェードは行わない。

雨滴の半径を3～4pxに拡大し、既存画素を滴の中心へ寄せて参照する。旧式で中心付近の変位が整数丸めにより消えていた部分も修正した。追加の光線や物理屈折は使わない。背景に明暗差を置くことで、花の外側でもレンズの揺らぎが見える。XMBは最後に重ねる。

## メモリ

- 森林モジュールの .bss / .data はともに0バイト。
- 16バイトのフレームパラメータを既存の花用共有ブロックへ追加。7776 → 7792バイト。別の所有者として共有メモリを奪わず、既存の解放・再利用に従う。
- 花モジュールの .bss / .data は変更前後で84 / 16バイトのまま（ESP32-S3向け単体コンパイル）。
- フェード用に自動変数の背景1行240バイトを使用。これは常駐配列ではないがスタックを使う。
- 雨滴の状態と行バッファ等は従来と同じ692バイト。
- 頂点や画像のFlash使用は増えないが、関数のコードはFlashを使う。ノイズ追加後の森林モジュールは -O2 単体オブジェクトで text 2491バイト、data / bss は0バイト。リンク後のファームウェア全体の差とは異なる。

PIEについては pie-simd.md の制約を確認済み。今回の森林はスカラー整数演算。最適化の効果は実機で測って判断し、他の背景の倍率を流用しない。
