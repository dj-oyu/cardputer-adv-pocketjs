# 花の背景アニメーション

2026-09-07。関数で開閉・回転する花をネイティブホームの背景として追加。
XMBの文字配置・サイズ・カテゴリ・選択表示・遷移は既存のまま。
花専用のメニューや時刻表示は置かず、背景描画後に共通の `draw_menu()` を呼ぶ。
Settings → Backgroundから選択する。従来の背景IDと保存値は維持する。

| ID | 名前 | 関数で作る形 |
| --- | --- | --- |
| 3 / 4 | FLOWER RAY / FLOWER MESH | 従来の放射状の花、解析曲面と生成メッシュの比較 |
| 5 | LILY OF VALLEY | すずらん。二次Bezierの茎、5つの開口した釣鐘、広い葉 |
| 6 | SUNFLOWER | ヒマワリ。角度で配置する26枚の黄色い花びら、黄金角の螺旋模様 |
| 7 | SNOWDROP | スノードロップ。垂れ下がる茎、3枚の白い外側の花びら、緑の内側 |

## Flashに頂点・画像素材を置かない

花のモデルファイル、頂点座標配列、テクスチャ画像は埋め込まない。
保持するのは生成式と、長さ・幅・色・茎の制御点など少数の形状パラメータのみ。
追加の3種はすべて光線と解析曲面の交点から描画し、メッシュを生成しない。
元のMESH比較モードの頂点も、実行時に三角関数からRAMへ生成する。Flashに座標列は存在しない。
ヒマワリの中心模様は `r(n)∝sqrt(n)`、`θ(n)=n×2.39996323` から起動後に1KiBのRAMへ生成する。
すずらんの釣鐘は半球状の上部と三次式の裾を6つの円錐帯に近似し、各帯との二次方程式を解く。底面は閉じず、開口越しの裏側も判定する。

## 実装

- 花は右120×108pxを中心に描画。既存XMBの文字は背景全体の上に重ねる。
- 従来種は7枚の花びらと中央部を薄い楕円体で表現。正弦関数で開花角と長さを変え、IMUの傾きを平滑化して反映。追加種は根元を保ちながら揺れ、形状パラメータで花びらの動きを生成。
- RAYは平行な一次光線と二次曲面の交点を解析的に計算。手前の交点と法線を用いて照明を計算する。
- MESHは同じ楕円体を1152三角形に分割し、法線を補間して同じ照明式で描画する。両方式とも画素中心で評価。
- 質感は拡散光、鏡面光、輪郭光、帯状の映り込みを組み合わせた近似。二次反射・屈折・透過・床反射は未実装。
- 240px幅の既存ストリップへ直接描画。奥行きバッファは120画素の1行分だけ。
- 比較用メッシュと行バッファ等の状態はホストのsizeof合計25,317バイト。スタック、配置のパディング、コード領域は含まない。比較版はアプリ実行中もこの静的領域を保持する。
- RAY選択中は三角形用の頂点生成を省く。背景更新は既存UIタスクの周期を利用する。

## 検証

ESP-IDF v6.0.1の `idf.py -B build_flower build` は成功。
3種追加・既存XMB復元後も、作業ツリー全体のバイナリは3MiBアプリ領域に約40%の余裕。
元の `approach` から `draw_menu` までのメニュー描画コードがHEADと完全一致することを検証済み。
Flash予約領域チェック、ホスト描画テスト、変更したPythonの構文検査も成功。
共有ツリーの他機能の変更を含むビルドなので、全体サイズを花単体の増分とは扱わない。

`tools/test_flower.c` は60姿勢について、ストリップと全画面の画素一致、先頭・末尾のガード、左側領域の保持、メッシュ頂点が解析曲面上にあることを検証する。
さらに追加3種を各60姿勢で検証。すずらん31、ヒマワリ36、スノードロップ20の解析曲面部品で構成。
釣鐘の側面の交点と、開口に架空の蓋がないことも独立した単体モデルで検証する。
両方式の輪郭不一致率は、描画範囲の和集合に対して3.63%。メッシュの離散化による差でありビット一致を求める比較ではない。

```powershell
$env:PATH='C:\msys64\ucrt64\bin;'+$env:PATH
gcc -O2 -Wall -Wextra -Werror tools/test_flower.c -lm -o .cache/test_flower.exe
.cache/test_flower.exe
python tools/preview_flower.py
```

プレビューはC描画結果に既存XMBの配置・フォントを重ねたホスト画像。LCDキャプチャではない。
`flower-gallery.png` は背景だけを切り出した3種の比較画像。
`preview_flower.py` は `build_flower/generated/fonts.h` を使用する。

## ガラスの雨（近似）

花背景（ID 3〜7）にだけ、背景描画後・共通XMB描画前のパスを追加。
起動後の最初は8〜16秒、以降は4秒の発生期間の後に18〜36秒空け、2〜5滴を時間差で生成する。
水滴は少し止まってから加速し、細い水筋とともに6〜8秒で消える。時刻は花背景が動作している時間。

描画済みの同じ横1行から数ピクセル以内の色を読み、位置ずれ・明暗の縁でレンズ感を近似する。
花の形状・照明・光線数を変えず、追加のレイトレーシング、物理屈折、別画面バッファは使わない。
全画面に広がる水滴でも、XMBの文字は最後に共通コードで重ねるため歪まない。
滴の状態と240画素の行バッファ等のsizeof合計は692バイト。雨の素材画像・頂点データはFlashへ置かない。

`tools/test_glass_rain.c` は300秒の時間経過、雨のない間の画素保持、1〜11行単位の分割描画一致、
画面左右端・最終行・滴の重なりのガードを検証する。固定seedの試験で10回の発生、200 wet / 493 dryサンプル。
`tools/preview_glass_rain.c` と `.py` は既存XMBを重ねた3秒のホストAPNGを生成する。
プレビューの15fpsは動画の再生設定であり、実機性能の測定ではない。追加パスの実機所要時間は未測定。

## 実機での計測

専用 `build_flower` でビルドする。`PERF mode=3/4` のprep・loop・kernel・hud・sendを別々に比較する。
花のkernelは背景描画全体のサイクル数で、既存波モードの「PIE行だけ」という意味とは異なる。花にはまだPIE命令を使っていない。
`tools/benchmark_background.py` は8種類を測定し、入力直後の最初の集計は遷移の影響を考慮して読む。
`capture_home.py` と `test_settings.py` も対応。背景数を決め打ちせず、`home_modes.py` がファームウェアの名前テーブルから取得する。

30fpsは目標であり、この変更時点では実機への書き込み・FPS・ヒープ残量・物理LCDの確認は未実施。
ホスト処理時間をESP32-S3の性能として扱わない。

PIE化は計測で支配的な部分を確認してから行う。光線交差の判別式は横方向に二次式なので、候補領域の8画素評価が候補。
平方根・法線正規化・固定小数点の誤差も含め、スカラー参照との比較が必要。PIEの既存海面の倍率を花へ流用しない。
製品版では片方の方式に絞り、比較用メッシュの常駐領域を削除できる。
