フリチラリアは多数の小花を穂状につける F. persica ではなく、F. meleagris をモデルとする。トケイソウは採用しない。カラーは既存種なので、追加7種には含めない。

エキナセアの接合形状（2026-09-09）：NC State Extension掲載のCathy Dewitt撮影「Flowers (Wake County, NC)」と実描画を比較。孤立した球状中心を低く幅広い形へ変更し、同じ傾斜軸に沿う付け根の輪をその内部へ重ねた。14枚の舌状花は各2個の重なった楕円体で、外へ広がってから垂れる。24→38部品、既存上限56と保存型は維持。画像・頂点・アニメーション状態の追加保存はないが、部品増による実機描画時間は未測定。全14種×60姿勢の境界・分割一致検査をASan/UBSan付きで通過し、名前付きPNGで接合を確認した。

フリチラリア専用の帽子形は、既存の6区間のベル交差判定に別の輪郭係数を渡す。肩をパフスリーブのように膨らませ、胴から裾へ少し絞り、縁だけ柔らかく開く。最大半径は基準の1.10倍で既存の判定範囲に収まる。追加は読み取り専用の係数48バイトで、今回の膨らみ調整による容量増はない。画像・頂点・部品ごとの保存領域は増やさない。模様は既存の座標計算を使い、深紫と控えめな薄紫を交互に配置する。

帽子形の検証（2026-09-08）：単独形状の肩・胴・裾の交差判定と全14種×60姿勢をASan/UBSan付きで通過。高速除算比較は3,628,800画素すべて一致。ベル早期除外200,990回中、誤った除外は0。名前付きの実描画PNGを目視確認し、`build_flower_models` のESP-IDFビルドとFlash容量検査を通過。実機への書き込みと速度測定は未実施。

ニゲラは [Wikipedia 日本語版「クロタネソウ」](https://ja.wikipedia.org/wiki/クロタネソウ)と[英語版 Nigella damascena](https://en.wikipedia.org/wiki/Nigella_damascena)も照合した。青い部分は萼片で、実際の花弁は小さく、園芸型では萼片が増える。今回の形は萼片10枚の八重型とし、直立する5本の花柱、淡い花糸と暗色の葯、花を囲む分岐した苞に部品を配分する。花糸と葯は1部品内の色分けで表現し、54部品で既存上限56以内に収めた。特定の栽培品種名は付けない。

形態の参考: [RHS チューリップ](https://www.rhs.org.uk/plants/tulip)、[RHS クロッカス](https://www.rhs.org.uk/plants/29659/crocus-vernus/details)、[RHS スイセン](https://rhs.crocdn.co.uk/plants/_/narcissus-topolino/classid.1000000300/)、[Kew カラー](https://powo.science.kew.org/taxon/urn:lsid:ipni.org:names:89403-1/general-information)。

モデル・頂点座標列・テクスチャは埋め込まない。少数の寸法から楕円体と開口した円錐帯を実行時に生成し、光線との交点を解析的に求める。カラーは曲面の切り取り条件で非対称にする。植物学的に厳密な再現ではなく、小画面で特徴が伝わる関数アート。
架空の CRYSTAL は列挙値、生成関数、専用材質と描画分岐から削除した。検証はヒマワリの楕円体と独立したベル曲面で引き継ぐ。不正な種指定時はスズランへ戻す。

スイセンは副花冠を右上へ開く方向へ向け、細い首から広い開口部へ軸方向の光の筋を通す。首（長さ0.32・半径0.16）と開口部（長さ0.38・半径0.35）を重ねる2曲面で、縁の広がりと内壁を見せる。斜めに伸びるシルエットと、明るい縁・琥珀色の内壁を組み合わせ、奥の花喉は1部品で補う。専用材質 `CORONA` は曲面の局所座標で光の筋、口元の明るさ、奥の光を計算する。面上の発光風表現であり、空間を照らす物理的な光源ではない。部品数19、既存の共有部品領域内に収まり、画像・追加バッファ・追加の光線・画素単位の三角関数を使わない。クロッカスは花筒を花被の内側まで重ねる。市松模様は曲面の局所座標から計算し、画像や追加の模様部品を持たない。

全種の株元は背景の草と同じ画面下端の外へ合わせた。以前の共通根元 `y=-1.35` は画面上の約115行目で、花だけを119行目で打ち切る処理も残っていた。共通根元を `y=-2.2`、描画下端を134行目へ変更し、背景の草の根元（142〜149行目）へつながる構成にした。クロッカスの独立した3本の花筒と細葉も共通の根元高さを使う。

形状生成は `main/scene/flower_species.c`、描画は `main/scene/flower.c`、共有部品型と上限は `main/scene/flower_parts.h`。`MAX_PARTS=56` と部品型のサイズは維持し、種ごとの常駐領域を増やさない。下記の以前のメモリ値は当時の記録であり、今回のコード量の測定値ではない。

## 森の光と雨

描画順は森林背景 → 花 → 雨滴 → 既存XMB。

[Horizon Forbidden West の世界表現](https://blog.playstation.com/2021/11/22/horizon-forbidden-west-an-authentic-world/)と[Guerrilla の大気表現資料](https://www.guerrilla-games.com/read/nubis-evolved)を参考に、等間隔の明るい斜線を避け、暖色の広い散乱光、青緑の霞、薄い遠景の幹、手前の草・シダを組み合わせる。AAAの体積描画技術を移植するものではない。

garden.c は行ごとの整数演算で近似する。光の密度は64pxと32pxの2層のValue Noiseを3:1で合成し、滑らかな低周波ノイズで光の中心も少し歪める。格子値は整数ハッシュから生成し、Q8 smoothstepで補間する。格子端の値は行内の自動変数へ保持し、画素ごとの再計算を避ける。LUT・画像・頂点配列はない。

草木は区画内の位置、高さ、幅、傾き、葉の間隔をハッシュで決め、密度ノイズで群生と空白を作る。近い草は共通の連続ノイズから風を受ける。40秒ごとの花交換時に森も再配置するが、幹・樹冠・草木は旧配置から新配置へ3秒のsmoothstepで重ね替える。主光の位置・幅・傾きも同じ係数で控えめに移行する。主光・補助光・虫・風の時間を継続し、光と虫は1回だけ描画する。以前は花が消えるフレームで植生を即時交換していたため背景が飛んで見えた。花の1.2秒のフェードにもsmoothstepを使う。全画面暗転や花の二重描画は行わない。植生合成には480バイトの一時行バッファ、主光形状に共有領域8バイト、移行状態に12バイトを追加する。詳細は `flower-transitions.md`。

雨滴の半径を3～4pxに拡大し、既存画素を滴の中心へ寄せて参照する。旧式で中心付近の変位が整数丸めにより消えていた部分も修正した。追加の光線や物理屈折は使わない。背景に明暗差を置くことで、花の外側でもレンズの揺らぎが見える。XMBは最後に重ねる。

## メモリ

- 森林モジュールの .bss / .data はともに0バイト。
- 16バイトのフレームパラメータを既存の花用共有ブロックへ追加。7776 → 7792バイト。別の所有者として共有メモリを奪わず、既存の解放・再利用に従う。
- 花モジュールの .bss / .data は変更前後で84 / 16バイトのまま（ESP32-S3向け単体コンパイル）。
- フェード用に自動変数の背景1行240バイトを使用。これは常駐配列ではないがスタックを使う。
- 雨滴の状態と行バッファ等は従来と同じ692バイト。
- 頂点や画像のFlash使用は増えないが、関数のコードはFlashを使う。ノイズ追加後の森林モジュールは -O2 単体オブジェクトで text 2491バイト、data / bss は0バイト。リンク後のファームウェア全体の差とは異なる。

PIEについては pie-simd.md の制約を確認済み。今回の森林はスカラー整数演算。最適化の効果は実機で測って判断し、他の背景の倍率を流用しない。

## 14種への拡張・ニゲラ修正の検証（2026-09-08）

以下は接地・副花冠の追加修正前の記録。最新の結果は次節を参照。

- `tools/test_flower.c` を WSL/GCC、`-O2 -Wall -Wextra -Werror -fsanitize=address,undefined` で実行。全14種×60姿勢の分割描画一致、描画境界、部品座標系、共有ブロックの解放・再利用、不正な種指定時の代替を通過。
- 153,848フレーム・128回の切替で全14種が出現し、種の交換は完全に消えたフレームで行われた。
- 共有ブロックはホスト実測10,480バイトで変更前と同じ。部品型のレイアウト、`MAX_PARTS=56` を維持。最大使用数はニゲラの54。
- `tools/test_flower_div.c` の全14種×8時刻、3,628,800画素の比較では2画素のみ色成分が1段階変化。輪郭の変化は0。
- `tools/test_bell_reject.c` の全14種×24時刻では148,065回のベル判定中56,818回を省略し、誤った除外は0。これは実機時間の改善率を示す数字ではない。
- ESP-IDF 6.0.1、`build_flower_models` でビルドとFlash領域検査を通過。モデル生成関数のリンクを確認し、CRYSTAL生成シンボルは存在しない。別作業の変更も含む共有ツリーのビルドなので、ファーム全体のサイズ差を花だけの増減として扱わない。
- C描画から全14種の個別PNGと一覧を生成して形状を確認。画像内の識別名と列挙値の並びも生成時に照合する。実機への書き込みは行っていない。
