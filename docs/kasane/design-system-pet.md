# デザインシステム: ペット適用仕様 v0.1

2026-09-13、実装前の案。[共通仕様](design-system.md)の最初の受け入れアプリを定義する。
現行の根拠は`apps/pet/pet.js`、`main/pet/pet_assets.c`、`main/pet/pet_pixels.c`、[画像設計](../apps/pet-asset-design.md)、[連携仕様](../apps/pet-companion.md)。

## 1. 維持する機能

3種×4配色の12匹、6表情、FEED/PLAY/SLEEP/NAME/PETS、選択中のペット、育成値、保存・復元、保存エラーを維持する。
名前は現行互換のASCII最大8文字。一般の日本語描画対応を名前入力対応と混同しない。
育成は表示中の経過時刻で進め、現行のdt制限を維持する。装飾アニメーションのフレーム数に依存させず、非表示中の育成追加は行わない。
定期保存・操作時保存・Esc時の保存順序を保つ。描画エラーが育成状態や保存済みデータを書き換えてはならない。

## 2. 配置

座標は半開区間。既存画面を基に文字とバーの間隔を明示する。

| 要素 | 矩形または位置 |

| タイトル | (9,7)–(184,21) |
| バッジ | (190,7)–(238,21) |
| ペットパネル | (7,25)–(112,109)、角丸4 |
| 地面 | (15,94)–(104,96) |
| ペット | (27,29)、64×64、bobは1 px |
| 種名 | (15,99)–(111,108)、caption |
| 状態 | (122,29)–(238,43) |
| ステータス文字 | x=122..238、y=45/63/81、高さ12 |
| ステータスバー | x=122..228、y=58/76/94、高さ4 |
| 操作 | (7,112)–(236,124) |

バーは背景trackとfillの2命令で、幅は`round(106*percent/100)`。
パネルの垂直グラデーションは`#233d52`から`#142639`、境界は共通edge色。
小さい文字にはグラデーションを使わず、選択やエラーを色だけで伝えない。
新しい配置・色は画像デコーダーの互換性とは別に目視確認する。

## 3. 容量の受け入れ目標

ペット画面は32命令以内、文字予約512 B以内、同時トラック3件以内。
概算は背景1相当、タイトル/バッジ2、パネル/枠/地面/種名4、ペット1、状態1、ステータス9、操作2、ヒント1、吹き出し5の計26命令相当。
背景を画面属性として実装する場合はその分を減らせる。命令数は旧UIノード数と直接比較しない。
文字予約の案はタイトル48、バッジ16、種名24、状態48、ステータス3×32、操作96、ヒント96、吹き出し32の計456 B。
これらは設計見積もりであり、実装時に実際の最大文字列と使用量を検査する。

画像は既存PPT2のFlash 7,601 Bと1行128 B展開を維持する。
旧`show(node,index)`の全身テクスチャ経路は利用しない。
新しい`gfx.pet`は命令順とclipに従う。旧`place`は画面座標のオーバーレイなので、両方から二重描画しない。
旧API互換を残す場合はホスト側の明示的な層として管理し、同じdamage計算へ統合する。

## 4. 更新と演出

- 初回にreplaceし、育成値・選択・表情の変化はpatchする。直前値と同じsetterを繰り返さない。
- ステータスは2 Hzと入力時。定期的に全面replaceしない。
- 通常bobは1秒ごとに1 px。まばたきは約5秒ごとに200 msで、反応表情を優先する。
- 入力への反応は小さな上下移動、選択強調は約120 msの色補間を基本とする。
- 吹き出しは現行のASCII22文字、70 ms文字送り、2.4秒表示を維持する。全文を一度保存しrevealだけ更新する。
- 同時トラックは選択色1、反応移動1、文字送り1。反応移動中は通常bobを止め、同一属性を競合させない。
- 何も変わらない間はUI描画のために30 Hzで起床しない。育成の時間管理と表示の期限は分離する。
- ペット移動元と移動先、吹き出し消去位置の背景を再合成し、全画面転送へ戻さない。

## 5. companionと通知

CODEX/CLAUDE/ALARM/TIMERの情報取得、保存、操作契約を維持する。
通信結果が同じなら文字や画面を再生成しない。データ取得やNVSを描画関数から呼ばない。
システム通知は共通仕様の専用16命令/128 B/2トラック以内でアプリより上に表示する。
既存通知キューやタイマーのデータはサービス側に残し、全キュー分の描画命令を常駐させない。
通知とアプリの画面更新が重なっても、構築途中の状態を表示しない。

## 6. 検証

`tools/test_pet.cjs`の育成・保存・名前・操作の検証を維持し、旧UIの15ノード制限を新しい容量制約の検査へ置き換える。
モックだけで終わらせず実際のQuickJS bindingでも容量超過、文字更新、セッション終了を確認する。
`tools/test_pet_pixels.c`を基に12匹×6表情×2倍率とclip境界の画像一致を確認する。
新しいUI全体は全面スカラー描画を基準に部分描画と比較する。意図的な配色・配置変更は旧画面との全画素一致を要求せず目視で確認する。
静止10秒、バー1本更新、まばたき、bob、吹き出し出現/消失、通知重なり、起動終了100回を測る。
共通仕様の16 KiB native予算、JS増分、スタック、全体ヒープ、転送量、処理時間を個別に記録する。
これらが通るまで、省メモリ化の達成やPocketJS全体の除去完了を主張しない。
