# Shiki 仕様書 v1（草案）

版: v1 草案 1（2026-10-30）。状態: **レビュー前**。経緯・理由・計測は [shiki.md](shiki.md)、この文書は**規範**だけを置く。旧 API（`pocket.kasane.procedural` の float の plan）は [js-to-ir.md](js-to-ir.md)・[flash-plan.md](flash-plan.md)・コードが仕様で、この文書の対象外（§11 の移行で消す）。

## 0. 読み方

- 「〜する」「〜しなければならない」は規範。「推奨」は規範ではない。「（未決）」の項目は v1 の確定前に決める。
- 数値の上限は、コードで強制し、`limits`（§9.1）に出す値だけを書く。性能の数値は書かない（[shiki.md](shiki.md) と計測の文書に置く）。
- 用語: **式**（1 本のプログラム）、**handle**（登録した式）、**Shiki エンジン**（式を実行する native。QuickJS の VM とは別物）、**データ領域**（式が読み書きする型付きの配列）、**Q 形式**（固定小数の小数部のビット数。`Qf` と書く。例 Q16 は 1/65,536 刻み）。

## 1. 範囲と実行モデル

1. Shiki は、JS アプリが登録した式を native が実行し、Kasane の手続き面のフレームへ線分を出す仕組みである。式の種類は **線の式**（§4〜§6）と **格子の式**（§7）の 2 つ。
2. 描画タスクは 1 つで、式は JS の呼び出し（`draw`・`run`）の中で**同期に**実行される。Shiki エンジンが式を実行するのは、その呼び出しの間だけである。呼び出しの外で、データ領域を読み書きしてはならない。
3. 式の実行は有界でなければならない。命令の数・ステップ・線分・ラスタの上限（§9.1）を超える実行は `LIMIT` で止まる。
4. **決定性**: 同じ式・同じ引数・同じ入力・同じデータ領域の中身からは、どの実装経路（スカラー、PIE、host の参照実装）でも、ビット単位で同じ状態・線分・データ領域の書き込みを生まなければならない（§10）。

## 2. 数の型

### 2.1 型

| 型 | 中身 | 用途 |
| --- | --- | --- |
| `fixed` | 符号付き 32 ビット整数。値は `raw / 2^f`（`f` はその値の Q 形式、0〜30） | レジスタ、入力、引数、座標、計算 |
| `int` | `fixed` の `f = 0` | 回数、添字、色 |
| データ領域の要素 | `i16`・`u16`・`i32`。領域ごとに Q 形式を持つ（§5.1） | 表、点、状態 |

- float は Shiki のどこにも現れない。
- **Q 形式は命令が持たず、式の書き手と変換器が決める**（§8.3）。Shiki エンジンは整数の命令だけを実行する。Q 形式の変換は、掛け算のシフト量（§4.3 `MUL`）と `SHIFT` 命令で表す。
- 色は `int`（0〜65,535）で、固定小数として扱わない。

### 2.2 演算の規則

| 演算 | 結果 |
| --- | --- |
| 加減算 | 32 ビットに**飽和**（−2^31〜2^31−1） |
| 掛け算 | 64 ビットの積を `s` ビット**算術右シフト**（切り捨て、負の無限大方向）してから飽和。`s` は命令が持つ（0〜62） |
| 左シフト | 飽和 |
| 右シフト | 算術右シフト（切り捨て） |
| 比較 | 符号付き整数の比較 |
| 正弦 | §4.4 の表（実装に依らず決まった値） |

- 0 での割り算は命令に無い（割り算は変換器が定数の逆数の掛け算か、2 の冪ならシフトへ下ろす）。
- **非有限の値は存在しない**ので、旧 API の「非有限なら draw ごと失敗」は無い。

### 2.3 JS との境目

- JS の数（double）を `fixed`（Q 形式 `f`）へ変えるときは、`v × 2^f` を**最も近い整数に丸め、半分は 0 から遠い方へ**（`lround` と同じ）、そのあと飽和する。有限でない数は `INVALID_ARGUMENT`。
- 入力・引数の Q 形式は式が宣言する（§6.1）。JS は実数のまま渡し、変換は native が行う。
- データ領域は、JS が要素の型のまま（`Int16Array` などの生の整数で）書く。Q 形式への換算は JS 側の責任。

## 3. 式の構成

1 本の式は次を持つ（登録時に固定し、以後変わらない）。

| 項目 | 内容 |
| --- | --- |
| 命令 | 1〜64 個（§4） |
| 入力の宣言 | 0〜8 個。それぞれ Q 形式 |
| 引数の宣言 | 0〜8 個。それぞれ Q 形式と、当てはめる命令の欄（組み込みの式の `$n` と同じ） |
| データ領域の宣言 | 0〜4 個。それぞれ要素の型・Q 形式・1 レコードの要素の数と、読むだけか書くか |

## 4. 線の式の命令

### 4.1 状態

- レジスタ `r0`〜`r15`（`fixed`、32 ビット）。draw の始めにすべて 0。
- ペン（座標と有効か）。draw の始めに無効。
- ループの段（8 段まで）。データ領域の段（`EACH`）も同じ 8 段に数える。
- フレームへ出した線分。

### 4.2 命令の形式

1 命令 12 バイト: `op`（8 ビット）、`dst`・`a`・`b`（各 8 ビット）、`imm`（符号付き 32 ビット）、`aux`（16 ビット）、予約 2 バイト（0 でなければならない）。

### 4.3 命令

| 命令 | 動き | 失敗 |
| --- | --- | --- |
| `SET dst, imm` | `r[dst] = imm` | |
| `INPUT dst, a` | `r[dst] = 入力[a]`（宣言した Q 形式で変換済み） | |
| `ADD dst, a, b` | `r[dst] = sat(r[a] + r[b])` | |
| `SUB dst, a, b` | `r[dst] = sat(r[a] − r[b])` | |
| `MUL dst, a, b, s=aux` | `r[dst] = sat((r[a] × r[b]) >> s)`（64 ビットの積） | |
| `SHIFT dst, a, imm` | `imm > 0` なら飽和する左シフト、`imm < 0` なら算術右シフト | |
| `SIN dst, a` | §4.4 | |
| `REPEAT imm` / `REPEAT_REG a` / `END` | ループ。回数は `imm`（1〜255）か `r[a]`（`int` として 0〜255） | 回数が範囲外なら `INVALID` |
| `BREAK_IF_GT a, b` | `r[a] > r[b]` なら、いちばん内側のループ（`EACH` を含む）を抜ける | ループの外なら `INVALID` |
| `MOVE a, b` / `PLOT a, b, aux=色` / `LINE a, b, aux=色` | 座標（§4.5）。`PLOT` は 1 点、`LINE` はペンから線分 | 座標が範囲外なら `INVALID`、上限で `LIMIT` |
| `PLOT_C a, b, dst` / `LINE_C a, b, dst` | 色を `r[dst]`（`int`、0〜65,535）から | 色が範囲外なら `INVALID` |
| `CUBIC dst, a=分割数, aux=色` | `r[dst..dst+7]` を 4 つの制御点として、`a` 本の線分（§4.6） | 同上 |
| `LINE_PATTERN dst, a, b, imm=周期, aux=色 A` | 模様線（§4.7）。`r[dst..dst+5]` が模様・色 B・位相・幅 | 同上 |
| `EACH a=領域` / `FETCH` / `PUT` / `LOOKUP` | §5 | |

`dst`・`a`・`b` がレジスタを指すときは 0〜15、命令が複数のレジスタを使うとき（`CUBIC`・`LINE_PATTERN`・`FETCH`・`PUT`）は、その範囲がすべて 0〜15 に入っていなければ登録で拒否する。

### 4.4 正弦

`SIN dst, a`: `r[a]` を Q16 の**回転数**（1 周 = 65,536）として、下位 16 ビット `p` を位相に使う（整数部は周期で消える）。

1. `quad = p >> 14`、`w = p & 0x3FFF`。`quad` が 1 か 3 なら `w = 0x4000 − w`。
2. `i = w >> 6`、`t = w & 63`。`T` は 257 個の `i16` の組み込み表 `T[k] = round(sin(k·π/512) · 32767)`（k = 0〜256）。
3. `v = T[i] + (((T[i+1] − T[i]) · t) >> 6)`（Q15）。
4. `quad` が 2 か 3 なら `v = −v`。`r[dst] = v << 1`（Q16）。

表の中身と手順は v1 の一部で、変えるには版を上げる。ラジアンからの換算（`1/2π` の掛け算）は変換器が入れる。

### 4.5 座標

- 描画の命令は、レジスタを **Q16** の画素の座標として読む（他の Q 形式の値は、変換器が `SHIFT` か `MUL` のシフト量で Q16 にしてから渡す）。
- 画素への変換は `floor(raw / 65536)`（切り捨て）。最も近い画素にしたいときは、変換器が 0.5 を足してから渡す。
- 座標の範囲は −480〜720（画素）。外れたら `INVALID`。

### 4.6 `CUBIC`

`a` 本に等分した `t = k/a`（k = 1〜a）での 3 次ベジエを、制御点（Q16）から整数の演算だけで求める。正確な手順（係数の Q 形式と丸めの位置）は（未決）で、v1 の確定前に参照実装と一緒に決める。分割数は 1〜255。

### 4.7 `LINE_PATTERN`

旧 API の模様線（[crowd-primitives-design.md](crowd-primitives-design.md)）と同じ出力の形式（2 エントリ）を作る。弦の分割と位相の進め方を整数で定めた手順は（未決）で、`CUBIC` と同時に決める。

## 5. データ領域

### 5.1 宣言と結び付け

- データ領域は Shiki のヒープ（§9.2）に確保し、JS には型付き配列の窓として渡す（§9.3）。
- 1 つの領域は、要素の型（`i16`・`u16`・`i32`）、Q 形式（0〜30）、1 レコードの要素の数 `k`（1〜8）、要素の数 `n`（`k` の倍数、上限は `limits`）を持つ。**大きさは確保したときに決まり、変わらない。**
- 式の領域の宣言（§3）と、登録時に渡した領域は、型と `k` が一致しなければならない（不一致は `INVALID_ARGUMENT`）。
- **結び付けは登録時に固定する。** 1 つの領域を複数の handle に結び付けてよい。

### 5.2 命令

| 命令 | 動き |
| --- | --- |
| `EACH a` | 領域 `a` のレコードの数（`n / k`）だけ回すループ。カーソルは 0 から始まり、`END` で 1 進む。レコードが 0 個なら本体を飛ばす |
| `FETCH dst, a, b=位置, aux=個数 m, imm=シフト` | いちばん内側の `EACH a` のカーソルのレコードの、`b` 番目から `m` 個の要素を `r[dst..dst+m−1]` へ。各要素は `imm` だけシフト（正は飽和する左、負は算術右）して Q 形式を合わせる |
| `PUT dst, a, b=位置, aux=個数 m, imm=シフト` | 逆向き。`r[dst..dst+m−1]` を `imm` だけシフトし、要素の型へ**飽和**して書く |
| `LOOKUP dst, a, b=添字のレジスタ, aux=添字の小数部のビット数 g, imm=シフト` | `i = clamp(r[b] >> g, 0, n−1)` の要素を、`imm` だけシフトして `r[dst]` へ。**範囲外は端に寄せる**（ユーザー決定）。`k = 1` の領域だけ |

- `FETCH`・`PUT` は、同じ領域の `EACH` の中になければならない。`b + m ≤ k` でなければならない。これは登録時に検査し、実行時の範囲検査は無い。
- `PUT` は、宣言で「書く」とした領域にだけ使える。

### 5.3 書き込みの規則（`PUT`、ユーザー決定で v1 に入れる）

1. **書き込みは命令の順に即座に見える。** 同じ draw の中の後の `FETCH`・`LOOKUP` も、同じフレームの後の draw も、書いた値を読む。
2. **JS は、`draw` が戻った後に書いた値を読める**（同じメモリの窓、§9.3）。`draw` の途中で JS が動くことは無い。
3. **draw が失敗しても（`INVALID`・`LIMIT`）、それまでの書き込みは戻らない。** フレームの線分は捨てられるが、データ領域は書いたところまでで残る。
4. v1 の書き込みは、`EACH` のカーソルのレコードの中だけ（添字で任意の場所へ書く命令は無い）。

## 6. 登録時の検査

登録は、少なくとも次を確かめなければならない。1 つでも外れれば `INVALID_ARGUMENT` で、handle を作らない。

1. 命令の数が 1〜64。すべての `op` が既知で、予約の欄が 0。
2. レジスタの番号と範囲（§4.3）、入力の番号が宣言の数未満。
3. `REPEAT`／`EACH` と `END` の対応、入れ子が 8 段以内、`BREAK_IF_GT` がループの中。
4. §5.2 の、`FETCH`・`PUT` の位置と `EACH` の対応、`PUT` の領域が書ける宣言。
5. 引数を当てはめた後の命令でも 1〜4 が成り立つ（引数が `REPEAT` の回数や色を決めるため）。

**draw のたびには検査しない。** 登録後は命令・引数・領域の結び付けが変わらないことが前提で、実装はこれを構造で保証しなければならない（組み込みの式の表は const、配列で渡した命令は登録時に Shiki のヒープへ写す）。

## 7. 格子の式

v1 では、今の `pocket.kasane.grid` の int16 の IR（`CONST`・`LOAD`・`ADD`・`MUL`・`MIN`、[grid-js-notation.md](grid-js-notation.md)）を、そのまま `pocket.kasane.shiki.grid` に移す。意味は変えない。線の式との番地の規則（ループの添字の 1 次式）の統一は v2。

## 8. `@shiki` の記法（JS で書く式）

### 8.1 形

[js-to-ir.md](js-to-ir.md) §5 の `@plan` の部分集合（R1〜R6）を引き継ぎ、印を `@shiki` にする。足すもの:

```js
/** @shiki prail inputs: x, dx, z, dz, posts, r, colour, top
 *  @q z=24, dz=24, pz=24
 *  @data seats: i16 q8 record 3 write */
function prail() { ... }
```

### 8.2 足す書き方

| 書き方 | 命令 |
| --- | --- |
| `for (const [a, b, c] of seats)` | `EACH` ＋ `FETCH` |
| `seats.put(a, b, c)`（`for...of` の中で） | `PUT`（そのレコードへ） |
| `table[i]`（`i` は式） | `LOOKUP` |
| `a - b` | `SUB` |

### 8.3 Q 形式（ユーザー決定: 書き手が宣言する）

1. 入力・引数・変数の Q 形式は `@q 名前=小数部のビット数, ...` で宣言する。宣言しない名前は **Q16**。色・回数・添字は `int`（Q0）で、宣言できない。
2. 式の値は、**それを受け取る側の Q 形式**で計算する。代入なら代入先、描画の座標なら Q16、他の式の項なら（下の規則で決まる）その項の Q 形式。
3. `+`・`−` の項は、結果の Q 形式へ `SHIFT` で揃えてから計算する。
4. `a * b` は、`a`・`b` がそれぞれの Q 形式（名前なら宣言、式なら結果の Q 形式）を持ち、`MUL` のシフト量を `fa + fb − f結果` にする（負になるなら `SHIFT` を足す）。2 の冪の定数での割り算は、このシフト量に畳み込む。
5. 数の定数は、使われる場所の Q 形式で最も近い値に丸める。
6. 変換器は、宣言から決まらない場所（例: シフト量が 0〜62 に収まらない）をエラーにし、ファイル・式・行を示す。値の範囲は推定しない。

[shiki.md](shiki.md) §5.6 の `prail` の書き直し（奥行きを 256 倍）は、この記法では `@q z=24, dz=24, pz=24` に当たり、Newton の更新の `/ 256` は `MUL` のシフト量に吸収される。

### 9.2 Shiki のヒープ

- アプリは manifest で予算を宣言する: `shiki: {bytes: N}`。セッションの開始時に、N バイトの連続した区画を 1 つ確保する。確保できなければ、アプリを起動しない。
- フレーム・作業領域・式・点・データ領域は、すべてこの区画から取る。足りなければ、その呼び出しが `LIMIT_EXCEEDED` で失敗する（OOM ではない）。
- 区画は `app_stop()` で、ゲストを壊した**後に**丸ごと捨てる。
- 宣言の無いアプリは Shiki を使えない（`kasane.shiki` の `available` が false）。

### 9.3 データ領域

- `shiki.data({type: 'i16' | 'u16' | 'i32', q, length, record})` は、Shiki のヒープ上に領域を作り、その窓（`Int16Array`・`Uint16Array`・`Int32Array`）を返す。中身は 0。
- 窓は ArrayBuffer として外部メモリを指す。**解放は、JS の窓と、その領域を結び付けたすべての handle の両方が手放したとき**だけ行う（[shiki.md](shiki.md) §4.6 の規則 3）。`unregister` で最後の handle が外れると、Shiki は窓を detach し（長さ 0 になる）、領域を解放する。
- 伸びる ArrayBuffer、`transfer()` で移した窓は受け付けない（`INVALID_ARGUMENT`）。

### 9.4 呼び出し

| 呼び出し | 引数 | 誤り |
| --- | --- | --- |
| `register(name, args?, options?)` | 組み込みの式の名前 | 名前が無い、引数の数・値、領域の不一致: `INVALID_ARGUMENT`。handle の上限: `LIMIT_EXCEEDED` |
| `register(code, args?, options?)` | 命令を詰めた `Uint8Array`（12 バイト × 個数）。登録時に一度だけ Shiki のヒープへ写し、JS の配列は以後使わない | 同上 |
| `options` | `{data: [領域, ...], points: {...}}` | |
| `unregister(handle)` | | 古い handle: `CLOSED` |
| `beginFrame(color, surface?)`・`draw(handle, ...inputs)`・`commit()`・`resource(...)`・`createSurface(...)` | 旧 API と同じ意味。`draw` の入力は §2.3 で変換する | 旧 API と同じ |
| `grid.*` | §7 | 旧 API と同じ |

組み込みの式の命令の詰め方（12 バイトの並び）は、`register(code)` の詰め方と同じでなければならない。

## 10. 検証の要件

1. **参照実装**: host（Node）の参照実装を 1 つ持ち、Shiki エンジンの C と全命令・全状態で**ビット単位で一致**しなければならない。`tools/kasane_ir/q16_error.mjs` の固定小数の規則が出発点。
2. **経路の一致**: PIE へ下ろした経路は、同じ入力でスカラーの経路とビット単位で一致しなければならない。一致しない経路は採らない。
3. **捕獲した入力**: DERBY・MEGADEMO・BIG WAVE の捕獲した入力とランダムな入力で、参照実装と C が一致すること、および double で計算した意図の座標との誤差を記録すること（[shiki.md](shiki.md) §5.5 の形）。
4. **実機**: 実機でしか起きない不具合（評価中の `null`、strict aliasing など）がこのプロジェクトにはあるので、host だけで済んだことにしない。

## 11. 旧 API からの移行

1. Shiki エンジン（整数）と参照実装、登録時の検査、試験。旧 API は並べて残す。
2. `@shiki` の変換器（Q 形式の宣言、`SUB`・`SHIFT`、正弦の表）。
3. DERBY の式の移行（`prail`・`pt` は [shiki.md](shiki.md) §5.6 の書き直し、`pocket.derby.ser()` は奥行きを 256 倍して渡す）。MEGADEMO・BIG WAVE。
4. データ領域（`EACH`・`FETCH`・`PUT`・`LOOKUP`）と Shiki のヒープ。
5. `EACH` の本体の PIE への下ろし。
6. すべてのアプリが移ったら、旧 API（float の plan、`pocket.kasane.procedural`、`gridFold` のグローバル）を消す。
