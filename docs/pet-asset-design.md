# ペット画像の省容量化方針

2026-09-07: ユーザー承認済みの設計方針。PPT2形式と省メモリ描画を実装済み。

## 共用するものと差分

- 猫・ウーパールーパー・鳥の基本形をそれぞれ1個持つ。
- 各種4タイプの色違いはパレットで表現し、全身画像を複製しない。
- 配色だけで表現できない模様だけを差分データとして用意する。チャトラのしま、三毛の斑点、サイバーの装飾などが対象。差分不要のタイプには画像を持たない。
- 現在の色違い画像にある微細な輪郭・陰影の違いは、基本形への整理で吸収する。元画像を完全復元するための差分は保存しない。
- 基本形の色番号は体・影・目などの役割に対応させる。模様は変更する領域と色番号を持ち、重ねた後にパレットで発色させる。

## 表情と吹き出し

- 顔の位置を種ごとに固定し、目・口は基本形から分離する。まず座標と描画パラメーターで表現し、全身の表情別画像は作らない。
- 描画順は基本形、模様、目・口、吹き出しとする。表情変更で模様を消さない。
- まばたき・上下移動・文字送りは時間と数値で制御する。吹き出しの枠・しっぽは図形描画し、セリフ画像やアニメーションの連番画像を持たない。
- 定型文は共用し、文字送り中の文字列生成やフォント領域の再構築を避ける。

## 容量と検証

透明色込み16色、64×64の4ビット画像なら基本形3個は6,144バイト。16色×2バイトのパレット12個は384バイト。模様差分・管理情報・描画コードは別途必要。

模様は小さな矩形、走査行ごとの区間、ビットマスクなどを実データで比較し、デコーダーのコード容量も含めて形式を選ぶ。小さなデータに無条件で圧縮を適用しない。

既存画像は1匹につき92〜202色あるため、16色への整理後に輪郭、三毛模様、黒猫の視認性、サイバー色を確認する。容量の削減値は変換後に測定する。保存容量と実行時メモリは分けて計測し、展開バッファの二重保持や表情変更ごとの全身画像再アップロードを避ける。

## 実装結果

- 埋め込み画像: 98,304 → 7,601バイト（92.27%削減）。基本形3,217、配色384、模様3,584、索引・ヘッダー416バイト。
- 各行は4ビット生データ32バイトと色・長さのRLEを比較し、小さい方を保存する。193個の行索引で途中の行にも直接アクセスする。
- 模様は画素位置12ビット＋色番号4ビットのソート済み差分。行の先頭は二分探索する。
- 通常表示の画像用ヒープ確保は0。作業画素は1行128バイト。ESP32-S3向け`-Os -fstack-usage`では描画関数のフレーム192バイト、呼び出す顔描画は48バイト（外側の呼び出し元は別）。全身テクスチャ8,192バイトを常駐させない。
- 吹き出しは同時に1個、ASCII最大22文字、保存バッファ23バイト。70 msごとの文字送り、2.4秒で消える。既存5×7フォントを使い、文字画像も動的フォントアトラスも作らない。日本語セリフは未対応。
- `place(index,x,y,mood=0)`のmoodは通常0・眠い1・喜ぶ2・驚く3・空腹4・ウインク5。index=-1で非表示。画面座標で通常UIの上に描き、通知はさらにその上に描く。ノードの重なりやクリップを継承するAPIではない。
- ペットの画像・表情・吹き出しは全アプリ共通の1枠。終了時に状態を消す。目覚まし等の通知は同じデコーダーを使い半分の32×32で表示する。
- 旧`show(node,index)`互換経路はテクスチャが必要で、切り替え時に展開用8 KiB＋テクスチャ8 KiBのピークがある。同梱アプリはこの経路を使わない。`place`に切り替えると互換テクスチャを解放する。
- 表情・位置の更新は最大10 Hz、ステータス表示は2 Hzとキー操作時。定期まばたきは表情1で両目を200 ms閉じ、反応の表情を優先する。位置・表情が同じならオーバーレイ側から再描画を要求しない。LCD転送は既存の全画面方式を維持する。

全12匹の全画素、2倍率、画面外クリップ、6表情、不正形式をホストのAddressSanitizer/UBSan付きテストで確認。育成・保存・名前・連携操作はNodeテスト、統合は`build_pet_compact`でビルド確認。ブラウザでは描画と文字送りを確認した。実機への書き込み・実機の総ヒープ／消費電力測定は未実施。
