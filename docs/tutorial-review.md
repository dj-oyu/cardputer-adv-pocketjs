## 見直しの範囲

### 1. 共通APIの章を足すか、足さないか

まず決めるのはここで、足すのが自明ではない。今の9章は
「print が出る → 間違いを読む → 変数 → 画面 → 文字 → 座標 → キー入力 → 日本語」
という、プログラミングそのものを知らない人向けの並びになっている。
`pocket.storage` や `pocket.sensors` はその線の続きではなく、別の線の始まりに見える。

候補は2つ。
- **A: 既存9章の後ろに数章足す。** 10章「保存する」(`pocket.storage`)、
  11章「傾きを読む」(`pocket.sensors`)、12章「音を鳴らす」(`pocket.audio`)。
  どれも1行で結果が出て、`await` を教えずに済むものを選ぶこと。
  `pocket.storage.get` は Promise を返すので、ここは書き方を先に決める必要がある。
- **B: チュートリアルは今のまま据え置き、`pocket.*` は別の入口（リファレンス、
  またはサンプルアプリ）に回す。**

Bを推す理由がある。9章は「JavaScriptを知らない人」に向いていて、
`pocket.*` を使いたい人はもうその段階にいない。それでも共通APIに
触れる導線がないのは事実なので、Bを採るなら Tab のリファレンス表
(`lessons.c` の `REFERENCE`) を `pocket.*` の一覧に拡張するのが最小の答えになる。

決めるのはこのタスクの最初の仕事。決めずにコードを触らないこと。

### 2. vim風エディタの操作をどこかで教える

これは範囲に必ず入れる。ユーザーからの明示的な依頼。

現状、エディタのモードはフッターのバッジしか説明していない。
チュートリアルの章はいま insert モードで開くので（`26c70b7`）、
学習者はモードを知らないまま9章を終えられる。それでいい。
つまりvimの説明はチュートリアル本編ではなく、**Playground側**に置くのが筋。

置き場所の候補:
- `codeedit.c` の `notice` は `C-R RUN  C-S SAVE` を出している。ここは狭い。
- Tabのリファレンス表と同じ仕組みで、Playgroundにも一枚のヘルプ面を出す。
  `h`/`j`/`k`/`l`、`w`/`b`、`0`/`$`、`gg`/`G`、`i`/`a`/`o`、`x`/`dd`/`p`、
  `u`、`/`、`:w`/`:q`/`:q!` あたり。実装済みの範囲は `main/ui/vimcmd.c` が正。
  実装していないもの（visual、`.`、redo、`%`）を書かないこと。理由もそこにある。

ヘルプ面を足すならノード数とDRAMを測ること。`tools/memlog.py` が入口。
チュートリアル画面はタフィのノード崖（17ノードで29,648B）に近い作りをしている。

### 3. 章の文面の点検

- 5章「画面を塗る」の `globalThis.frame = () => {}` の説明は、
  ライフサイクル（§5）が入った今も正しいか。
- 8章のキー定数 `0x4000` を直書きしている。共通APIに名前付きの定数があるなら
  そちらへ寄せる。無いならこのままでよい。
- `REFERENCE` の数字表はプロパティ番号のまま。ここが `ui.*` の生の面である以上、
  `pocket.ui`（§6）との関係を一行でも書いておくと迷いが減る。
