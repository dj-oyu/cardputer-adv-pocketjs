# DERBY WATCH: FINISH のスローと HEAD ON のダストオーバーレイ、手描き風の帯

2026-10-02、ブランチ `vm/finish-fx`（`vm/main` fac3552 から）。ユーザーの決定（FINISH のスローを特別な画にする、残像・ブラーは高いので使わない）の実装と測定。数値には **実測（host）／実測（実機）／推定** を付ける。見た目の評価は書かない（ユーザーが画と GIF で選ぶ）。

## 結論

- **何を足したか**: FINISH のスロー中（`cm === 3`）に、ダスト 3 層（奥の点・中間の粒・手前のボケ）と、上下 3 本ずつの手描き風の帯。HEAD ON（`cm === 6`）では、既定で奥と中間の層だけを、馬の**前に**（馬が手前に来るように）描く。どちらも不透明な線だけで、乱数はフレームと位置の `sin` だけから作る（レースの乱数列に触らない）。
- **plan**: 3 本（`dust` 60 命令・`bokeh` 56・`band` 57）。枠は**どの場面でも 31/32**（ゲート 29+2、レース中は帯がゲートの枠を引き継ぐ、写真は帯を外して `photo`）。
- **決定論**（host 実測）: 11 構成すべてで、着順・時計・種・デモ＝手で走らせたレース・オッズ・保存の行が vm/main と同一。画素は FINISH と HEAD ON のフレーム**だけ**が違い、それ以外のフレームは全行一致（フレームごとの画素ハッシュで比較、例: MID の台本 14,527 フレーム中、違うのは 1,125 = FINISH 727 + HEAD ON 398）。
- **費用**（実機 MID、同じ diag image で同じ種のデモを効果あり 3 回／なし 2 回、レースごとの中央値の中央値）:
  - FINISH: JS のターン **+2.0 ms**（うち VM の描画 +1.42 ms）、転送前の描画（render）+0.49 ms。draw +4、線分 +142、VM ステップ +1,993。fps は 29.4 → 29.7（フレームの上限に当たったまま。差は揺れの範囲）。
  - HEAD ON（①）: JS **+1.03 ms**（VM +0.66 ms）、render +0.05 ms。fps は 29.4 → 29.4。
  - **見積もり（0.3〜0.5 ms、補足後の目標 0.5〜0.7 ms）には合わない。FINISH は約 2.5 ms（約 4〜5 倍）**。内訳と削る候補は §4。
- **メモリ**:
  - ゲスト（host m32）: 評価後 **+1,012 B**、評価のピーク +1,088 B、GC 後の最大 +1,296 B。依頼の目安（+150〜300 B）を超えた。
  - ゲストの最大（実機 diag image、6 レース）: 基準 138,192〜138,920 B → 139,036〜139,736 B。140,000 B まで**残り 264 B**。レースを重ねても増え続けない。
  - 評価の余裕（実機 heapprobe、各 2 回で同値）: 22,675 B → **21,362 B（−1,313 B）**。20 KB の線まで 1.4 KB。
  - ネイティブ（実機）: ターン内の最小 25,856 → 23,856 B（≥ 11,208 B）、ゲートのターンの最小 31,668 → 29,676 B（≥ 23.5 KB）。`LOADSTALL`・`FRAMEFAIL`・`LOADFAIL`・`DEMOFAIL`・OOM はどちらにも無い。

## 1. 構成

### 層と描く順

| 層 | plan | FINISH（既定 B） | HEAD ON（既定 ①） | 描く順 |
| --- | --- | --- | --- | --- |
| 奥（far）: 1 px の点、きらめきで白 | `dust`（layer 0） | 16 px に 1 個 | 20 px に 1 個 | コースの後（HEAD ON は馬の前） |
| 中間（mid）: 3 px の粒 | `dust`（layer 1） | 34 px に 1 個 | 40 px に 1 個 | 同 |
| 手前（near）: ボケ（8 角形のリング） | `bokeh` | 48 px に 1 個 | 切 | HEAD ON の馬の後 |
| 手前の流れる線（C） | `dust`（layer 3） | 切 | 切 | 同 |
| 手描き風の帯 | `band` | 上下 3 本ずつ | 切 | 最後（ミニマップの前） |

- **ミニマップ（y 2〜12）は帯の後に描く**ので、帯がマップを隠すことはない。上の帯は y 15 付近から始め、下の帯は y 131 から上へ（`BT`・`BS`）。HUD の文字（view の text ノード）は手続き描画の上に重なるので、常に帯の上に出る。FINISH の馬の足元は最も手前のレーンで y 121、下の帯は y 126〜134。
- **HEAD ON の順**: `hd`（背景）→ 奥と中間の dust → 馬（`fr` × 8）→ 手前のボケ（③④）→ マップ。描く順を入れ替えたのは HEAD ON の馬のループの位置だけで、効果が無いフレームの draw の順は前と同じ（画素の全行一致で確認）。

### 粒の置き方（スクロールしても粒が保たれる）

各層は「幅 w px のスロットの列」。JS は層ごとに、列の動き（パララックス × カメラのパン、＋漂い）から、最初のスロットの x（−2w〜−w）とその番号を出す。plan はスロットごとに `u = sin(h)`（h は番号 × 黄金角 2.39996、mod 2π）と、`sin(u·137 + t)`・`sin(u·97 + tw)` で位置・大きさ・きらめきを決める。同じ粒は同じ番号なので、カメラが動いても粒の見た目が保たれ、画面の外に余分な粒を置かない。

- **パン**: 切り替わり（カット）からのカメラの移動 `(cx − cx₀) · f / 16`（奥行き 16 m の馬の面の px）× 層のパララックス。HEAD ON は静止カメラなので 0。
- **漂い**: 横は `0.15 px/フレーム × パララックス`、縦は `sin(u·137 + t)` の t（`0.003/フレーム`）。
- **帯のボイリング**: 3 フレームに 1 回（約 10 fps）、6 枚の絵を順に繰り返す（セルアニメの「ボイル」と同じ。毎回新しい乱数にするより引数が小さく保てる）。1 本 10 区間、y のずれ・傾き・ゆがみの大きさ・色（白・暗いセピア 0x7202・明るいセピア 0xCD0D の順）をストロークごとに変える。太さは「近い 2 本が重なって太く見える」で出す（間隔 2.5 px）。

### `sin` の引数は ±200 以内（実機で効いた）

最初の版は `sin(h·7)`・`sin(h·3)` で h を 12.9898 ずつ足していたので、引数が数百〜千を超えた。newlib の `sinf` は約 201 を超えると遅い範囲縮約に入り（[derby-background-cost.md](../kasane/derby-background-cost.md) の「SIN が引数約 201 超で約 7〜9 倍遅い」と同じ）、実機で **dust 1 draw 600 µs**、FINISH の JS +3.2 ms だった。引数を 200 以内に収めた形で **dust 1 draw 326 µs**（実測）。あわせて、`sin(12.9898·i)` は 2π を法とすると `sin(0.42·i)` と同じ値で、乱数ではなく滑らかな波だった（隣のスロットが似た位置になる）ので、黄金角の刻みと `sin(u·137)` の連鎖に替えた。

## 2. パラメータの表（ユーザーが調整する所）

すべて [apps/derby/derby_prog.js](../../apps/derby/derby_prog.js) にある。

- **`KN[4]`（JS 側、1 本の配列）**: 0〜4 が FINISH、5〜9 が HEAD ON の「奥・中間・手前・流れる線のスロット幅（px、0 で切）、帯の本数（片側）」。10〜13 が層ごとのパララックス、14 が横の漂い（px/フレーム）、15 が t の進み（1 フレームあたり）、16 が帯の描き直しの間隔（フレーム）。17〜19 は実行中に `paint()` が書く（カットのフレーム・cx・カメラ）。
- **plan の先頭の行の定数**（ビルド時。ゲストのヒープを使わない）:
  - `dust`: y の範囲 `Y0`・`YH`、きらめきの閾値 `SPK` と速さ `TW`、`RISE`（D 用）、層ごとの長さ `L0`・`L1`・`L3` と色 `C0`（奥、淡い黄 0xFFD9）・`C1`（中間、淡いセピア 0xE695）・`C3`（流れる線 0xEF7D）、きらめきの色 `C2`（白）。
  - `bokeh`: 半径 `R0`（±30%）、重ねる 8 角形の数 `N`（1 でリング、2 以上で内側を 1 px ずつ `FILL` の色で塗る＝「塗りの円」）、縁の色 `RIM`（暗い暖色 0x7B28）、`FILL`（0x3984）。
  - `band`: 色 3 つ、上端 `BT`・下端 `BS − BT`、間隔 `GAP`、傾き `TILT`、ゆがみ `AMP0 + AMP1 × 本目`、区間の長さ `SEG`。
- **パターンの切り替え**（`KN[4]` のコメントにも同じ表）:

| パターン | `KN[4]` 0〜4（FINISH） | ほか |
| --- | --- | --- |
| A（手前ボケ＋奥の粒） | 16, 0, 48, 0, 3 | |
| **B（3 層、既定）** | 16, 34, 48, 0, 3 | パララックス 0.2 / 0.5 / 1 |
| C（B＋手前の流れる線） | 16, 34, 48, 90, 3 | 流れる線のパララックス 1.2 |
| D（B＋奥の粒を馬場に固定、下から上へ） | 16, 34, 48, 0, 3 | `KN[4][10]` = 1、`dust` の `RISE` = 80（約 0.24 px/フレーム。奥の層だけ） |

| HEAD ON | `KN[4]` 5〜9 |
| --- | --- |
| **① 馬の後ろだけ（既定）** | 20, 40, 0, 0, 0 |
| ② 馬の後ろ＋手前ボケ | 20, 40, 60, 0, 0 |
| ③ 手前ボケだけ | 0, 0, 60, 0, 0 |
| ④ なし | 0, 0, 0, 0, 0 |

- **パララックスの定義**: 1 = 奥行き 16 m（馬の面）と同じだけ動く。指示どおり手前 1.0・中間 0.5・奥 0.2 にした（物理的には手前ほど大きく動くので、手前を 1 より大きくする選択もある）。
- **カメラ別**: CLOSE は未実装（`paint()` の `q` が FINISH と HEAD ON だけを選ぶ）。足すなら `KN[4]` に 5 個の行と、`q` の選択に 1 項。
- 色・形を変えたら再ビルド（plan は firmware の flash の表）。`KN[4]` だけの変更もアプリの埋め込みなので再ビルドが要る。

- **帯の区間を 10 → 6**: 帯の VM 0.47 → 約 0.3 ms。

- 実機の費用は効果あり 3 回・なし 2 回の 1 回の起動。FINISH の fps の差（29.4 → 29.7）は上限に当たったままの揺れで、効果の向きを表していない。
