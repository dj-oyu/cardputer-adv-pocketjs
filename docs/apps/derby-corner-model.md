# DERBY WATCH: 楕円コースのカーブ補正（host の試算）

2026-09-30、ブランチ `vm/corner-sim`。**数値はすべて host（Node）の Monte Carlo の実測で、実機の値ではない。** 出荷コード（`apps/derby/`）は変えていない。試作は `tools/games/derby_corner.mjs`。

## 結論

- **補正は「進み」の乗数にする**（`x += v·dt·m`）。目標速度 `g` に掛ける案は、先頭との差で引き戻す項と体力の消費に吸われて、同じ `a` でも枠の差が約 1/4 しか出ない（下の「採らなかった案」）。
- **内外差 `a` は 0.1〜0.25%**（最内 +a、最外 −a、カーブ 377 m で最内と最外の差は 0.75〜1.9 m）。枠の勝率の差（最良の枠 − 最悪の枠）は `a` 0.1% で 1.4 pt、0.25% で 3.2〜3.4 pt、0.5% で 6.8 pt、1% で 14 pt。「数ポイント以内」なら 0.25% が上限。
- **ばらつき `s` は 1% では見た目にほぼ効かず、2% から効く。** 本命（1 番人気）の勝率は直線 43.2% に対し、`s` 1% で 42.9%、2% で 40.4%、4% で 33.2%。カーブ中の順位の入れ替わり（2 頭の前後が入れ替わった回数、1 レースあたり）は 7.8 → 8.2 → 9.1 → 10.8 回。`s` 2% は進みの ±7.5 m に当たるが、後半の競り合いの項（先頭から 4 m 以内で加速）と前半の追走の項が差を詰め直すので、着順への効きは小さい。
- **`s` を上げると、ゴール前が静かになる。** ラスト 300 m の先頭交代は直線 1.77 回 → `s` 2% で 1.47、4% で 1.13。カーブで付いた差が残るため。着差の中央値も 0.59 → 0.73 → 1.01 m。
- **オッズは、賭ける側に見える情報だけで作る**（2026-09-30 の方針。下の「公開情報だけのオッズ」）。入れるのはパドックの能力値、コースの種類、枠（パドックで NO.1〜8 と枠色が見える）だけ。カーブごとの馬ごとの乱数は入れない。
- **直線用のオッズをそのまま使えるのは弱まで。** 中（`s` 2%）では 8 番人気の期待値が 1.19 になり、大穴買いが得になる。枠の項を足しても 1.16。**全体の温度（0.92）と払い戻し係数を合わせると、中で 14 群の最大ずれが 0.076**（8 番人気 0.86、1 番人気 0.79）。強では温度 0.71 で 0.036。
- 馬ごとの重みをすべて推定し直す版（下の「参考: 全重みの再推定」）は、神の視点ではない（公開情報だけ）が、方針により採らない。
- **枠は毎レース抽選と同じ。** `field(seed)` は 8 つの枠それぞれに、プールから名前を、乱数から能力値を毎レース独立に引く。馬（名前＋能力）は枠に固定されず、レースをまたいで同じ馬は存在しない。だから**枠順の抽選は要らない**。ただしオッズは枠を見る必要がある（内枠が有利なのをオッズが知らないと、内枠買いが得になる）。
- **直線のレースは変わらない。** カーブの乱数は別の列（`rng(seed + 0x2545f491)`）から 8 回引き、レースの列（`seed + 0x5bd1e995`）の引き方は変えない。`derby_corner.mjs verify` で、補正を持たないレースが出荷の `step()` と全ステップの `x`・`v`・`e` と `tc` で全桁一致（2,000 種、`CORNER_VERIFY PASS`）。
- **推奨: 中（`a` 0.25%、`s` 2%）＋オッズ (c)（直線の重み＋枠 0.15、温度 0.92、係数 0.787）を第一候補、弱（0.1%、1%）＋オッズ (b)（枠の項だけ）を控え。** どれを採るかはユーザーが決める。

## 試作したモデル

```
m_i = (1 + a·(3.5 − i)/3.5) · (1 + s·(2·u_i − 1))      i = 0（最内）〜7、u_i ∈ [0,1)
step():  y = x + v·dt · (273 ≤ x < 650 ? m_i : 1)
u_i:     rng(seed + 0x2545f491) の i 回目（アプリの rng() と同じ mulberry32）
```

- `u_i` はレースの始めに 8 回引いても、カーブに入るときに引いても同じ値になる（別の列なので、順番が他の乱数に影響しない）。
- 乗数は `v` にも体力 `e` にも掛けない。表示する速度・脚の回転と体力の消費は直線と同じで、「内を回った分だけ前に出る」「その日の手応え」だけが位置に出る。
- 実際の幾何なら、レーンの奥行き（12〜21.2 m、`DL`）の差 9.2 m で半周 π·9.2 ≈ 29 m、最内と最外で約 ±3.8% の差になる。これをそのまま入れると枠の差が数十 pt になるので、距離は計算しない（要望どおり、演出としての速度差）。

## 公開情報だけのオッズ（2026-09-30 の方針）

### 方針

1. オッズは、賭ける側がオッズを見る時点で見られる情報だけで作る: パドックの能力値、コースの種類（直線／楕円）、枠。
2. カーブで馬ごとに引く乱数 `u_i` は入れない。**試作でも入れていない**: `derby_corner.mjs` のオッズは `r.h`（パドックの能力値）と枠番 `i` だけから計算し、`u_i` は `run()` の中で乗数 `st.cm` にしか渡らない（`rows` に残さない）。
3. 較正は馬ごとの重みを推定し直さず、全体のパラメータだけを動かす。人気順ごとに 0.8 へ厳密には揃えない。ただし、本命買いが得（期待値 > 1）になる設定と、8 番人気の期待値が 1 を超える設定は不可。

### 枠はパドックで見えている（コードで確認）

- **枠 = 馬番 = 走るレーン。** `field(seed)` の `h[i]` は、レースで `DL[i]`（i 番目の奥行きのレーン）を走る（`derby_view.js` の `course()` の `const p = f / DL[l]`）。
- **パドックのオッズ板**（`derby_scene.js` の `if (pad)`）は、枠色（`SILK[i]`）の見本とオッズを i = 0〜7 の順に並べる。選択中の馬は `num(pick)`（`'NO.' + (i + 1)`）と名前で出る。
- 枠が決まるのは `field()` を呼ぶ時点（パドックに入ったとき）で、オッズと同じフレーム。賭ける前に見えるので、枠の項は公開情報。

### 3 通りのオッズ

`node tools/games/derby_corner.mjs public 80000 <a> <s> --json`。8 万レースの偶数番目で推定し、奇数番目（4 万レース）で測る。オッズの式は出荷の `odds()` と同じ形（大穴の裾 `c` 0.0015、1.1〜999、0.1 刻み）。

読み方:
- **`s` 1% までは温度が 1 のまま**（弱・中間で γ 1.00）。ばらつきが勝敗に効かないので、直線の強さの尺度がそのまま使える。(b) で足りる（最大ずれ 0.074〜0.087、8 番人気 0.81〜0.89）。

## 採らなかった案

| 案 | 理由（host の実測、各 4 万レース） |
| --- | --- |
| 目標速度 `g` に乗数を掛ける（`--mode=g`） | 同じ `a` で枠の差が小さい: `a` 0.25%・`s` 1% で 0.8 pt（進みなら 3.4 pt）、`a` 1%・`s` 4% でやっと 4.9 pt。`v` が `g` に追いつくのに時間がかかり、速い分は体力の消費（`v > EB·top`）で払わされ、後半の競り合いの項が引き戻す。つまみの効き方が体力のモデルに依存して、読みにくい |
| 実際の幾何（レーンの奥行きから半周の距離を出す） | 最内と最外で約 ±3.8%。`a` 1% で既に枠の差 14 pt |
| 枠順の抽選を足す | 枠と馬の対応がもともと毎レース新しい（上）ので、意味がない |
| カーブの乱数をレースの列から引く | 楕円のレースで、以降のすべての乱数（ゆらぎ・つまずき）の位置がずれる。直線と同じ種で比べられなくなる。別の列なら、同じ種の直線と楕円の差がカーブだけになる |

## 推奨

オッズは公開情報だけ（上の (b) か (c)）。

- **第一候補: 中（`a` 0.25%、`s` 2%）。** 枠の差 3.2 pt（内枠 14.1%、外枠 11.0%）で「内が少し有利」が数字に出る範囲。1 番人気の勝率は 43.2 → 40.4%（−2.8 pt）、カーブ中の入れ替わり +17%（7.8 → 9.1 回）。代わりに、ラスト 300 m の先頭交代が 1.77 → 1.47 回に減る。オッズは (c)（温度 0.92、枠 0.15、係数 0.787、+57 B）。8 番人気 0.86、1 番人気 0.79、最大ずれ 0.076。
- **控え: 弱（`a` 0.1%、`s` 1%）。** 枠の差 1.5 pt、1 番人気 −0.3 pt、入れ替わり +5%。直線とほぼ同じレースで、オッズは (b)（枠の項 0.07 だけ、+26 B）。8 番人気 0.89、最大ずれ 0.087。**見た目の差はほぼ出ない可能性が高い**（着差中央 0.59 → 0.62 m）。
- **強（`a` 0.5%、`s` 4%）は、ゴール前の競り合いを削る。** 1 番人気 33%、入れ替わり +38% だが、ラスト 300 m の先頭交代が 1.12 回（直線の 63%）、着差の中央 1.01 m、ハナ差 7.7%。カーブで決まるレースが増える。オッズは (c) が必須（温度 0.71）。
- `a` と `s` は独立に効くので、中間（`a` 0.25%・`s` 1%: 枠の差 3.4 pt、1 番人気 42.9%）もある。オッズは (b)（枠 0.17）で最大ずれ 0.074。

面白さは実際に走るレースを見て決めること。host の数字は「どのつまみが何を動かすか」までしか言えない。

## 確信の低い点

- **「カーブ中の順位入れ替わり」は面白さの代理にすぎない。** 画面の見え方（カメラがカーブをどう映すか、楕円の描画）は、まだ無い。
- 入れ替わりは 1 ステップ（0.05 秒）ごとの前後の反転を数えるので、並走で細かく入れ替わる 2 頭も数える。直線との比較（同じ区間 273〜650 m）には使えるが、絶対値に意味は無い。
- オッズの重みは 4 万レースで推定し、別の 4 万で測った。直線の較正と同じ規模だが、`c` の選択は 4 通りの格子だけ。
- 乗数を進みにだけ掛けるので、脚の回転と前進がわずかに食い違う（下の「脚の回転と前進」。コードからの見込みで、描画では確かめていない）。
- 楕円の実装そのもの（コースの抽選、ミニマップ、カメラ、`--check` の楕円版）は、この文書の範囲外。

## 脚の回転と前進（コードから読んだ見込み、描画では未確認）

- **脚の位相は `v` から進む。** `derby_play.js` のレースのループは `ph[i] += rs.v[i] * DT / 6.5 * 2 * PI`（1 周期 6.5 m）。乗数 `m_i` は位置にだけ掛かるので、カーブ中は位相が前進に対して `1/m_i` 倍で回る。食い違いは中で最大 ±2.3%（`a` 0.25% ＋ `s` 2%）、強で ±4.5%。1 周期あたり中で約 0.15 m。
- **画面では、ほぼ見えない見込み。** 脚は地面に固定した接地点を持たず、胴の位置 `X` に対して `sin(ph)` で振るだけ（`derby_view.js` の `course()` の `'r' + l` の引数、CLOSE の `g0`〜`g5` のコマ）。足が地面を滑るのを比べる基準が画面に無く、脚の回転の 2〜4% の違いは速さの違いとして読めない。芝の刈り目はカメラと一緒に流れ、馬ごとではない。
- **他に `v` を使う所は、カーブの外か、影響が小さい。** 着差（`derby_scene.js` の `m = a * rs.v[o[1]]`）はゴール、ホームストレートで乗数が掛からない。カメラの追従（`derby_view.js` の `cx + (tgt − cx)·.12 + max(v)·DT·.88`）は、先頭の前進との差を毎フレーム 12% ずつ詰めるので、数 % の差は遅れとして溜まらない。
- **厳密に合わせる安い方法:** 位相を前進量から進める（`ph[i] += (rs.x[i] − rs.px[i]) / 6.5 * 2 * PI`）。`px` は `step()` がすでに持っている。直線のレースでは `x − px = v·dt` なので、位相は今と同じ値になる（浮動小数の丸めの順序が変わるので、全桁一致かは要確認。位相は表示だけで、レースの結果には効かない）。
