# LEVEL WAVE 背景

傾きに合わせて水平を保つ水面と、上から降る光。夜空にネオンのオーロラが2本、水面の縁が光の線で、上空の光の筋が水面で屈折し、水中に光の筋とコースティクス（光の網）を落とす。実装は `main/scene/wave.c`。

2026-10 に作り直した。以前は暗い青緑の帯3本と星だけだった。

## 計算しているもの

| 対象 | モデル | 費用の目安 |
| --- | --- | --- |
| 水面 | 1次元の線形浅水波（ノード61個、4px間隔、閉じた壁）。重力は傾きに追従し、静止形は `tan(傾き)` の勾配。体積は更新式の形で厳密に保存される | 120Hz の部分ステップ、1フレーム最大5回 |
| うねり | 波長 320 / 190 / 120 px、振幅 8 / 6.5 / 3.5 px の3本（2本は右、1本は左へ）。深水波の分散関係 ω=√(gk) に従い、長い波ほど速い。振幅はそれぞれ 30〜60 秒周期で 0.4〜1.0 倍に揺らぎ、凪と大きなうねりが交互に来る | 毎フレーム |
| 風のさざ波 | 短い波2本（光を集める）。曲率 `A k²` が約 1/20〜1/60 で、焦点が水中に来る。うねりの山で最大 1.5 倍、谷で 0.5 倍まで強弱をつける | 毎フレーム |
| 光線 | 368本（画面外に左右64列ずつ）。角度は傾き＋太陽の傾き 0.30rad。水面の法線でスネルの法則（n=1.333、ベクトル形）を解く。平方根と割り算はビット技＋Newton の `rsqrt` だけで済ませる | 毎フレーム |
| コースティクス | 隣り合う光線の間をビームとして、その行での幅に均等に配る（狭まれば明るい）。差分配列に4回の加算で入れ、行ごとに1回の累積和 | 水面より下の行のみ |
| 水の色 | 深さで赤→緑→青の順に吸収（Beer-Lambert、1/e になる深さは赤 6 / 緑 12 / 青 20 行、水面の強さ 0.85）。光の筋は水面直下で明るく、20〜30 行で薄れ、底は暗い水になる。`tools/make_scene_tables.py` の `wave_water_*` を flash に焼く | 表引き |

水面の補間は Catmull-Rom、さざ波の正弦表は小数位置で線形補間している。どちらも、傾きが段になるとそれがそのまま規則的な光の縞（4px 周期など）になって見えたため。傾きは丸める前の曲線から取る（1/16px に丸めた値の差分は、深さで拡大されて筋になる）。

## 描画の分担

- **PIE カーネル `wave_row_pie`**: 3本の光る線（オーロラ2本と水面の縁）を、距離（1/4px単位、255で打ち切り）から6表（青緑・赤 × 3本、各256語、1KiB ずつ連続）を引いて足す。そこに行の光の面（空・空中の光の筋・水・コースティクス）を足し、RGB565 に詰める。すべて channel×128 の飽和加算なので、光が重なると白に飽和し、桁あふれで黒くならない。本体が約378Bで `loopgtz` の上限256Bを超えるため、`bnez` のループ。`tools/pie/stalls.py` で 0 ストール、推定 112 サイクル/8画素（推定。実測は未）。
- **C `wave_light_row`**: 行ごとの光の面を作る。水面より上は空のグラデーションと淡い光の筋、下は水の色＋屈折光。
- 星は水面より上だけに描く（`wave_overlay`）。

## メモリ

`scene_mem` の core を 8,688 B 借りる（以前は約 2.3 KB）。アプリが前面に出ると返すので、ゲストのヒープには影響しない。ホーム画面表示中の空きヒープは減る（core は共有で、最大の背景に合わせて伸びる。FLOWER は約 7.8 KB）。flash は表が約 7.7 KB 増える。**どちらも実機で `tools/memlog.py --port` による確認が要る。**

## 検証

- `python tools/pie/test_kernels.py` — カーネルのアセンブリを C 版の行（`#else` 側）の写しと全画素比較。
- `python tools/pie/run_models.py wave` — 距離・飽和加算・RGB565 詰めの算術を総当たり。
- `python tools/test_scene_tables.py` — 表の値域。
- `tools/test_wave.c` — 体積保存、静止時の勾配、strip 描画と全体描画の一致、傾きの全範囲（`-fsanitize=address,undefined` でも）。
- `tools/preview_wave.c` — ホストで連番の PPM を書く（傾けて戻す 4 秒。第3引数 `still` で傾けずに、うねりとさざ波だけを見る）。

実機での描画時間は未測定。ホスト上の見積もりでは、カーネル約 2〜2.5 ms、行ごとの C が約 4〜6 ms 増える（旧: draw=21.11 ms のうち kernel=1.67 ms）。30Hz の枠 33 ms に収まる見込みだが、`PERF` の行で確かめること。
