# 回転スパンの域外判定をスパン単位の区間判定へ（切替つき・厳密・既定は有効）

対象: `perf/kasane-anchor`、前コミット `590f5aa`（行ごとのアンカー表）の上。
実機には触れていない（`/dev/ttyACM0` は別セッション）。**ミリ秒は 1 つも無い**。
ここにある数は target ツールチェーンの `objdump`/`size` の実測、ホストで走らせた
テストの出力、`/tmp` の使い捨て掃引プログラムの出力である。
候補の位置づけは `docs/perf/kasane-image-transform-recon.md` §6 候補 B。

---

## 1. 変えたもの

回転経路は、footprint の矩形のうち**ソースの外に出る画素（レコン文書の場面で 39%）を
1 画素ずつ判定して捨てるために 1 画素あたり約 37 命令**を払っていた。これを
**スパン（16 画素以下の窓）単位の区間判定**に置き換え、丸ごと外だと証明できたスパンは
判定 1 回とスクラッチの消去だけで済ませる。切替は `g_ksn_image_rotate_reject`
（`ksn_render.h`、既定 `true`）。切れば従来どおり全画素を判定する。

### なぜスパン単位で判定できるか

- スパン内のアンカー（`sx`, `sy`）は**単調**である。1 画素の増分は `floor(su/um)` と
  `floor(sv/vm)` で、その符号は分子の増分 `step_u = 2c` / `step_v = -2s` の符号に一致し
  （`step_u > 0 ⇒ qu >= 0`、`step_u < 0 ⇒ qu <= -1`）、桁上がりは +0/+1 しか足さない。
- したがって「その軸の画素が全部 0 未満」は**最大値**で、「全部ソース幅以上」は**最小値**で
  決まる。最小・最大は両端のアンカーから分かり、減少側の端は「もう 1 画素先」の値なので、
  1 画素の商を 1 回引けば（`ux_end - qu - 1`）下限が出る。
- 両軸の区間がそれぞれ `[0, ソース幅)` と交わらなければ、そのスパンの画素は全部棄却される。
- **最初の画素が受け入れられるスパンは受け入れ画素を 1 つ持つ**ので、区間判定は
  「先頭画素が域外」のときだけ走らせる（これがスパンあたり 11 命令の前置フィルタ）。

スパンの先頭と「`x + count`」のアンカーは、**表が 16 画素幅のスパンを供給していれば
表が持つ 16 画素ぶんの増分対 1 組の桁上がり**で出る（除算なし・表の追加エントリなし）。
それ以外の幅では同じ規則の「`count` 画素ぶん」の増分対をその場で割って作る。

### 画素が動かない理由

棄却された画素に対してループが書くのは `scratch->rotated.rgb[i] = 0` と
`alpha[i] = 0` だけで、呼び出し側は `alpha = 0` の画素を合成しない
（直接経路は `blend` が `a == 0` で `dst` を返し、群の経路は `premultiply_over` が
`mul8(color & 255, 0) = 0` で `dst` をそのまま返す）。スキップ経路は同じ 0 を
`count` 個書いて戻るだけなので、**書き込まれる画素も取得されるブロックも同じ**である。

## 2. 厳密性

1. **掃引（ホスト、使い捨ての `/tmp/kanchor/reject_sweep.c`、リポジトリには入れていない）**:
   スパンの歩き方・アンカー・1 画素の加算ステップ・区間判定を書き写し、**画素ごとの
   判定で受け入れ画素を数えた結果**と突き合わせた。区間判定が「丸ごと外」と言った
   スパンに受け入れ画素が 1 つでもあれば不合格とする。

   ```
   reject sweep: spans 2632833732, accepted 22045735878, rejected 16323173142,
   interval tests 848590246, spans skipped 11088162339 (67.9% of rejected pixels),
   unsound 0,
     all-rejected spans the conservative test did not prove 20263694 (safe, no skip)
   PASS: every skipped span has no accepted pixel
   ```

   **26.3 億スパン・384 億画素の評価で「外れているのに外と判定した」例は 0**。
   逆に、全部棄却なのに証明できずスキップしなかったスパンは 2.0% で、
   これは**安全側**（スキップしないだけ）。
2. **アーム比較テスト（既存ハーネスを 5 アームへ拡張）**:
   `tools/kasane_contract/test_image_rotate_arms.c` は
   既定（表 + 区間判定）/ スパンごと除算 + 区間判定 / 画素ごと除算 / 表のみ / 除算のみ の
   5 アームを 1 バイナリに同居させ、場面をアームごとに作り直して全 32,400 画素・
   フレームハッシュ・provider の取得回数を比べる。

   ```
   animated track: 120 frames in every arm, alternating arm identical
   anchor table: 990409 builds, largest row served 15 entries
   span rejection: 2089935 interval tests, 1521819 whole spans skipped
   image rotate arms PASS: 11833 configs, 23665 panel hashes, worst pixel step 0, fetches identical
   ```

   11,833 通り、パネル比較 23,665 回（7.66 億画素値）、**最悪画素差 0**、取得回数一致。
   取得回数が一致することは「捨てるはずだった画素のぶんブロックを余計に取っていない」こと
   でもある。非空虚性は、`-DKSN_ANCHOR_COUNT` を付けたビルドで
   **区間判定 2,089,935 回・実際にスキップした 1,521,819 スパン**を数えて主張する
   （スイッチを無視する実装ならこの数は 0 になる）。カウンタはマクロの外では
   生えないので出荷オブジェクトには 1 バイトも入らない。
3. **リポジトリの全スイート**: `run.sh` を `/tmp` に複製し、sanitizer のフラグ文字列だけ
   外して `cd` をこの worktree に向けて実行 → **exit 0、全 PASS**
   （リポジトリの `run.sh` は 1 バイトも変えていない）。

## 4. 残っているもの

- スキップできたのは棄却画素の 58-68%（掃引全体では 67.9%）である。残りは
  **受け入れ画素と棄却画素が混ざったスパン**の端の棄却画素で、スパン内の受け入れ区間
  （両軸の単調性から連続した添字区間になる）を出すには端ごとに除算が要り、
  1 スパン 16 画素では割に合わなかった（実測: 判定 60 命令に対して棄却 1 画素 37 命令）。
- より大きい残りは**呼び出し側**である。棄却画素（`alpha = 0`）でも呼び出し側は
  1 画素あたり `image_sample_index` + `image_color` + `blend`/`premultiply_over` を
  回しており（レコン文書 §2 で約 102 命令）、ここを削るには行ごとの受け入れ区間を
  呼び出し側へ渡して `for` の範囲を縮める必要がある。**このファイルの外の変更**なので
  本コミットには入れていない。
- **実機の時間は未測定**。
