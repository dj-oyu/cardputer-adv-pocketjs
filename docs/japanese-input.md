# 日本語入力: SKK移植設計

状態: 方針確定 / 2026-09-06。移植元の調査と辞書・フォントの実測は完了。
変換エンジンの移植、QuickJS接続、実機表示は未実装。

## 目的

Hello Worldの次の段階で、SKK変換できる小さなテキスト欄を作る。
Editor、Docs検索、ペットの命名、PCエージェントへの指示で同じ日本語入力サービスを使用する。
同梱アプリもユーザーJSも変換エンジンを持たず、確定したUTF-8文字列を受け取る。

## 再利用元と範囲

参照: `dj-oyu/esp32p4-mqjs`、調査commit `a901d0e685dbc4cf48c505dabeaeb46532cc8679`。

| 再利用候補 | 役割 | 扱い |
| --- | --- | --- |
| skk_core/skk_kana.c | ローマ字変換、送り仮名、候補選択 | 純Cの状態機械を再利用候補とする |
| skk_core/skk_dict.c | 辞書イメージ検証・検索 | Flash直接参照の構造を維持 |
| skk_core/include/skk_core.h | 固定容量とデータ寿命 | 契約を維持する |
| ime_core | IMEの有効化、入力の消費・通過・確定 | アプリ共通の入力ポリシーとして使用 |
| tools/skk_prep.py | 辞書の事前生成 | PC側で実行。デバイスでは索引を生成しない |
| tools/tests/test_skk_*、test_ime_core.c | 変換と入力順序の回帰テスト | 移植時に引き継いで実行 |

MicroQuickJSバインディング、Tab5のLVGL描画、Tab5固有キーマップ、P4のpartition設定は流用しない。
既存skk_coreとime_coreはI/O、LVGL、ESP-IDF、動的確保を含まない。
`#include`は標準ヘッダのみで、ファイルスコープのstaticはすべてconstであり可変グローバルを持たない。
差し替えが必要なのは辞書のありかを決める`skk_builtin.c`と`skk_dict_image.S`だけで、
ADVでは`skk_dict` partitionをmmapしたblobを渡す。
`kbd_core`は`esp_timer_get_time()`を一箇所で使うため、現在時刻を引数で受け取る形へ変えれば純Cになる。

## メモリ

S3向けGCC 14.2.0（esp-14.2.0_20241119）で既存ヘッダーのsizeofを確認した。

| 構造 | byte |
| --- | ---: |
| skk_t | 1,272 |
| ime_t（skk_tを内包） | 1,296 |
| skk_dict_t | 240 |
| 1セッション＋共有辞書ハンドル | 1,536 |

これは全体のRAM消費ではない。スタック、辞書マッピング管理、表示キャッシュ、入力キュー、QuickJS文字列は別に測る。
固定容量は読み96byte、候補64件、preedit192byte、commit256byte。UTF-8の文字数ではなくバイト数。
候補は辞書内のoffset/lengthで保持し、64件をまとめてJS文字列へ展開しない。
表示中の候補と確定文字列だけを必要時にコピーする。

## 辞書

`skk_prep.py`でSKK-JISYOから生成したイメージのサイズを実測した。

| 辞書 | 見出し | image | 2MiB枠の残り |
| --- | ---: | ---: | ---: |
| S | 3,379 | 116,991 | — |
| M | 8,346 | 303,297 | 1.79MB |
| ML | 48,750 | 1,949,758 | 147,394 |
| L | — | 8.07MB | 収まらない |

MLは2MiBに収まる。まずMで経路を通し、確定後にMLへ差し替える。
`--max-size 0x200000`を必ず付け、超過時はビルドを失敗させる。
生成ツール、入力辞書revision、生成オプション、生成サイズ、payload CRC32を記録する。
`alphabet_crc32`はS/M/MLで同一の3840893823であり、辞書を替えてもイメージは無効にならない。

Flash内の専用領域をmmapし、headerの長さと境界を検証して必要範囲のみ参照する。
移植元のヘッダはこの経路を想定しており、`image_len`が`blob.len`より短くてよいと定めている。
mmap窓がページ丸めされる前提が既に入っているため、partition先頭をそのまま渡せる。
Flash辞書はセッション終了まで有効とし、使用中に差し替えない。独立した辞書領域はCRCも検証する。
SDは現実装のbase pointer参照に直接接続できない。全辞書をRAMへ読む回避策は採らず、必要なら別途ページ読み込み方式を設計する。
Tab5の8.5MB領域は8MB FlashのADVに移植しない。

## フォント

PocketJSのフォント口はDCFAアトラス一つで、字形は1ピクセル1byteのアルファ、
cmapのコードポイントはu32のためCJKも形式上は載る。
ただし`load_font_atlas`はRustコア側でVecへ全コピーするため、載せた分だけSRAMを消費する。
JIS第1水準を12pxで丸ごと積むと490KB必要で、アプリ終了後の空き340KB・最大連続221KBのADVでは成立しない。

そこでフォントの消費者を二つに分ける。

| 消費者 | 経路 | 字形の置き場 |
| --- | --- | --- |
| ネイティブのIMEオーバーレイ、Shell、テキスト入力欄 | strip合成時に自前で1bpp→RGB565展開 | Flashをmmapして直接参照 |
| JSノード内の日本語表示 | 表示中の文字だけでDCFAを組み`load_font_atlas` | SRAM、上限128〜256字 |

M2はネイティブ側だけで完了させ、テキスト入力欄もプラットフォームのネイティブ部品として合成描画する。
JSノードへ日本語を出す経路はM3へ分ける。
合成点は`render_strip`と`board_present`の間で、PocketJSのフレーム状態を汚さない。
damageのない領域は次フレームで再描画されないため、IME領域を閉じたときは全面再描画を要求する。

アトラス再ロードはlayout dirtyとraster revision更新を伴い全面再描画になるため、確定バッチ単位に限る。
1グリフあたりcoverage 144byteとcmap 8byteで152byte。
`Atlas::parse`は新しいVecを確保してから旧アトラスを捨てるため、
再ロードの瞬間はホスト側blob・新アトラス・旧アトラスが同時に存在し、**定常の最大3倍**になる。
128字なら定常19.5KB・ピーク58KB、256字なら定常38.9KB・ピーク117KB、
512字はピーク233KBで最大連続221KBを超える。
ホスト側blobをstatic常駐にしてピークを下げ、cmapはソート挿入して毎回組み直さない。

字形は東雲12pxを本命とし、実機で14pxと並べて確認する。

| 候補 | セル | JIS X 0208全6,879字 | ライセンス |
| --- | --- | ---: | --- |
| 東雲12 | 12×12 | 161KB | Public Domain |
| 東雲14 | 14×14 | 188KB | Public Domain |
| 東雲16 | 16×16 | 215KB | Public Domain |
| 美咲ゴシック | 8×8 | 54KB | 独自フリー |
| k8x12 | 8×12 | 81KB | 独自フリー |

東雲はPublic Domainで通知義務がなく、元がビットマップのため1bpp設計と字形が一致する。
Noto Sans JPはアンチエイリアス前提で1bpp化すると字形が崩れるため採らない。
M辞書の候補漢字3,031字、MLの4,587字はいずれもJIS X 0208に収まり、東雲なら欠字は出ない。
240×135では12pxで全角20桁×11行。8pxは漢字0.8mm角となり判読を実機で確認するまで採用しない。

3サイズ全部でも564KBのため`jp_font`の2MiB予約は過剰で、512KBへ縮めて残りをstorageへ回す。

Flash側の形式は辞書と同じ流儀に揃える。固定長ヘッダ、コードポイント昇順のcmap、固定長1bppセル、CRC。
12pxなら1字24byteで、S3のFlashキャッシュが64byteライン単位で吸収するためSRAMキャッシュを別に持たない。
欠字はDCFAの規約に合わせgid 0の字形を描き、ネイティブ側も同じ字形を使う。

最初の表示試験はかなと固定テスト語の字形だけを用意する。その段階を「M辞書の全候補を表示可能」とは扱わない。
移植元のLVGLフォントはDCFAとも自前1bpp形式とも別物であり、そのまま持ち込まない。

## 入力経路

```text
TCA8418キーイベント（押下/解放と修飾キーを保持）
  → 専用ForceStopの検出（制御タスク、IME/JSの状態に依存しない）
  → フォーカス先を確定してIME所有タスクへ渡す
  → ime_feed()
      IME_TAKEN: preedit/候補表示を更新、アプリへキーを渡さない
      IME_TEXT: 確定UTF-8を所有バッファへコピー、TextCommitを送る
      IME_PASS: エディタ/JSの通常キー、未処理のBackをShellへ渡す
```

変換中のEscは取消、Enterは確定、候補操作はIMEを優先する。変換確定Enterを改行・送信・アプリ終了へ再利用しない。
通常Backと専用ForceStopを異なる論理操作として定義する。M1ではIMEがないためBackは従来どおりホームへ戻る。

現在の`board_key()`は解放イベントを捨て、押下のみを6キーに固定している。
修飾キーのheld状態を扱うため、公式デモと同じ4×14の対応表へ拡張し、押下と解放の両方を読む。

| 操作 | 割当 | 理由 |
| --- | --- | --- |
| 英数/かな切替 | Ctrl+J、補助でopt+Space | SKK標準。ADVは物理ctrlを持つ |
| 変換取消 | EscとC-g | Escは変換中のみIMEが消費する |
| Back | IMEが消費しなかったEsc | Fn+`` ` `` |
| ForceStop | Ctrl+Alt+Del | 三キー同時で誤爆せず、取消と重ならない |

移植元はCtrl+JがEnterと同じバイトへ潰れるためSKK標準の切替を諦めているが、
ADVはキー変換を自前で書くので潰す前に識別できる。修飾状態を落としてからIME切替を判断しない。
現在のBackは修飾なしの`` ` ``キーであり、文字入力を始めると衝突するためFn+`` ` ``へ移す。
IME切替操作は押下エッジのみ、文字と候補送りには意図したrepeatを適用する。

## セッション・スレッド・フォーカス

アクティブな入力欄に1つのime_tを割り当て、1タスクのみが操作する。辞書は読み取り専用で共有できる。
QuickJS contextはアプリタスクのみが触る。制御タスクからJSコールバックを直接呼ばない。
ime_text/preedit/candの借用ポインタをタスク間キューへ入れない。次のime_feed等で無効になるため、その場で長さ付きコピーを作る。
入力イベントにはフォーカス世代を付け、画面切り替え後に届いた古いTextCommitは捨てる。
フォーカス喪失・アプリ終了では未確定文字を破棄し、勝手に確定しない。確定済みの編集内容は保持する。
キューが満杯の場合は切り詰めたUTF-8を配送せず、入力を停止してoverflowを表示し、キー保持状態を再同期する。
辞書未搭載・検証失敗時は英数入力を維持し、IME利用不可を表示する。全体を起動失敗にしない。

## 表示とJS API案

通常時は小さな英数/かな表示、入力中のみ下部に1〜2行の変換領域を出す。
preedit、選択候補、候補番号を表示する。候補は1件ずつ切り替え、長文を画面外へ無制限に展開しない。
ネイティブIMEの描画はDisplayServiceでアプリ描画後に合成し、LCDへの別タスクの直描画を禁止する。
IME領域が閉じた際は背後のアプリ領域を再描画する。strip境界と合成後のdamage管理も検証する。

以下は本プロジェクトのAPI案であり、PocketJSの既存APIではない。

- 入力欄がフォーカス取得時にtext inputを開始し、終了時に解除する。
- アプリはTextCommit（UTF-8文字列）と未消費のKeyイベントを受け取る。
- preeditや候補選択はプラットフォームが表示し、アプリの文字列にはまだ入れない。
- EditorはUTF-8境界で削除・移動する。全角文字を1byte/1pixelとして扱わない。
- JSコード編集は英数で開始し、コメントや文字列を入力するときにユーザーが切り替える。

現行実装は変換学習・ユーザー辞書を持たない。辞書の候補順を維持する。
注釈表示、concat形式、一部の送り仮名別候補グループなど既存の制限は、移植後も対応済みと宣言しない。

## 実装順序

失敗したときの手戻りが大きいものから並べる。

1. 辞書partitionの実機検証。イメージを焼き、mmapして`skk_dict_open`をVERIFY付きで通し、検索を1,000回計測する。
   CRC時間、検索時間、2MiB窓のmmapの可否を測る。ここが崩れると以降の設計が変わる。
2. skk_coreとime_coreをコンポーネントとして取り込み、ホストのgccで既存テストを通す。
   このPCにgcc/clangがないため、ホストテストはWSL側で実行する。
3. キーボードの全マトリクス化。押下と解放の両方を読み、修飾キーのheld状態を持つ。
4. 東雲BDFから1bpp形式を生成し、`jp_font`へ書き込み、strip合成点で固定文字列を描く。12pxと14pxを並べて確認する。
5. IMEオーバーレイ。preedit、候補、モードを下部1〜2行にネイティブ描画する。完了条件1、2、6に対応。
6. 確定UTF-8のJS配送。完了条件3、4、5、7に対応。
7. 計測。完了条件8に対応。

JSノードへ日本語を出す動的アトラスはM3とし、M2の完了条件には含めない。

先に潰しておくリスクと最小検証。

| リスク | 最小検証 |
| --- | --- |
| 動的アトラスがRAMを圧迫する | 12×12×256字のダミーDCFAを足し、空きと最大連続の変化を測る |
| 辞書とフォントの二領域同時mmap | 手順1と同時に、命令キャッシュとの競合で打鍵遅延が出ないか測る |
| アトラス再ロードの全面再描画 | 毎フレーム再ロードする最悪ケースでフレーム時間を測る |
| 修飾キーの同時押し復元 | 全イベントをrow/col/stateでログし実機で確認する |
| 12pxの可読性 | 手順4で12と14を並べる |

## M2: 日本語入力欄の完了条件

M1のQuickJS Hello Worldとメモリ検証後に接続する。

1. 英数/かな切替、ローマ字→かな、送り仮名、候補巡回・確定を本体で操作できる。
2. 変換中Escで取消でき、アプリは終了しない。ForceStopはIME/JS動作中でも有効。
3. 確定した「かんじ→漢字」などのUTF-8がJSの入力欄に一度だけ届く。
   入力欄はネイティブ描画のため、到達はTextCommitのログと受け取ったバイト長で検証する。
4. 未確定文字がJSの送信操作へ漏れず、Enterの確定で同時送信されない。
5. フォーカス変更・画面遷移で候補が残らず、古い入力が次のアプリへ届かない。
6. 読み/候補/commit上限、キューoverflow、辞書なし・破損、欠字を処理できる。
7. 日本語の削除・再編集がUTF-8を壊さない。
8. 変換前後のRAM、stack余裕、辞書検証時間、検索時間、入力表示遅延をADVで記録する。

移植元リポジトリはGPL-3.0-or-laterを宣言しているが、その理由はwolfSSL/wolfSSHの同梱であり、

著作権者自身の判断としてMITで再提供し、取り込む各ファイルの先頭にSPDX-License-Identifierと著作権表示を付ける。

辞書はコードと別の配布物として扱う。SKK-JISYOはGPL-2.0-or-laterであり、
配布イメージへ`skk_dict`を含めると配布物全体にGPLの義務がかかる。
