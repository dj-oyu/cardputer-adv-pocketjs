# SOLAR SAIL

8惑星をゆっくり巡る第3のホーム背景。
SETTINGS → BACKGROUND → SOLAR SAIL で選択し、確定時に保存する。
既存の LEVEL WAVE / OCEAN + STARS の保存番号は維持する。

水星→金星→地球→火星→木星→土星→天王星→海王星の順に巡る。
各24秒滞在＋12秒移動、全周288秒。移動は速度・加速度が端で0になる
補間を用い、距離に応じてカメラの倍率も滑らかに変える。
画面右下に対象名を表示する。メニューは従来位置に固定する。

## 天文学モデルと表現上の区別

- [NASA/JPLの近似軌道・Table 1](https://ssd.jpl.nasa.gov/planets/approx_pos.html)
  の6要素と経年変化率を用いる。ケプラー方程式を解き、J2000黄道座標で
  太陽中心の3D位置を計算する。距離はAUの線形尺度を維持し、楕円の
  離心率、軌道傾斜、公転の速さを反映。惑星間の重力を直接積分しない。
- 未同期時の起点はJ2000（JD 2451545.0）。背景表示1秒でモデル時間を0.25日進める。
  時計が同期済みなら現在UTCから求めたモデル日数を使い、実時間の速さで進める。
  デモでは適用範囲外への外挿を避けるため、
  約16時間の連続表示で2040年相当の位置に到達した後は公転を止め、
  カメラ巡回は継続する。アプリ表示中はデモと巡回を止め、
  同期済みの公転位置は復帰時の現在UTCへ更新する。
- 地球の太陽系内の位置は元表に従い地球・月重心で近似。
  月を地球記号の周りに描くが、重心に対する地球の微小な揺動は省略する。
- ワイヤ球の軸は[NAIFのIAU定数](https://naif.jpl.nasa.gov/pub/naif/generic_kernels/pck/pck00011.tpc)
  を使う固定近似。火星は同資料にある2009年平均極。歳差・章動、
  表面地形、自転経度は再現しない。格子は表面模様ではない。
- 光の方向はモデル内の太陽位置から計算する。土星の環は赤道面に置き、
  前後を描き分ける。環の幅・線数・色は模式化し、他惑星の薄い環は省略。
- 惑星本体は対象を半径24px、その他を2pxに誇張する。衛星のある地球・
  木星・土星はそれぞれ20/11/18pxへ引いて衛星系を見せる。太陽も記号サイズ。
  本体の大きさ、星の配置、カメラの移動は観賞用で、実縮尺や実探査軌道ではない。
  本モデルは高精度暦や観測・航法計算の代用を意図しない。

## 将来のWi-Fi / 時刻同期との接続

`main/solar_time.c` が時計と天体描画の境界になる。
描画側は `solar_time_now(demo_elapsed_seconds)` からモデル日数と時刻源を受け取る。
巡回・IMUの演出時間は単調な描画時間を使い、システム時刻と混ぜない。
背景の左下には、同期済み時計使用中は `UTC`、それ以外は `DEMO` と表示する。

- 起動時は明示的に未同期。OSの時計がそれらしい年でも勝手に信用しない。
- Wi-Fi実装時は、システム時計への同期が完了した時点で
  `solar_time_set_synchronized(true)` を呼ぶ。別タスクから安全に通知できる。
- 以後は `gettimeofday()` をフレームごとに読み、惑星・衛星の共通時刻にする。
  Unix UTCを直接使うため、日本時間などのタイムゾーン設定に依存しない。
- Wi-Fi切断時には `false` を通知しない。最後に同期したOS時計で継続する。
  時計自体が信用できなくなったときのみ `solar_time_set_synchronized(false)` を呼ぶ。
  同期状態をNVSには保存しない。再起動後の信頼回復は将来の時計サービスが判断する。
- 日時取得失敗・不正なマイクロ秒・2000年未満・2050年以上はデモに戻す。
  戻り値の `source` で未同期・取得失敗・範囲外を識別可能。範囲外日時を
  別の年へ丸めて「現在」と表示しない。2038年以降も64bit Unix秒で扱う。
- 初回同期や時刻補正は次フレームで公転位置へ反映し、巡回対象・巡回速度を
  リセットしない。年単位の補正をアニメーション時間として早送りしない。
  公転配置自体は切り替わるため、時刻の大幅な補正時は画面内の位置が変わり得る。

[ESP-IDF v6.0.1のSNTP API](https://docs.espressif.com/projects/esp-idf/en/v6.0.1/esp32s3/api-reference/system/system_time.html)
との接続例（Wi-Fi / SNTPサービス自体は今回追加していない）:

```c
#include "solar_time.h"

// 即時同期のコールバック、またはシステム時計の補正完了を確認した箇所。
solar_time_set_synchronized(true);
```

SNTPのsmoothモードでは、受信した目標時刻の通知とOS時計の補正完了を区別する。
時計サービス側が補正完了を確認してから通知すること。

時刻変換は `JD(UTC) = Unix秒 / 86400 + 2440587.5` を使用する。
軌道資料が指定するTDBに対してUTCを表示用途の近似として扱い、TT−UTCの閏秒差と
TT−TDBは補正しない。厳密な暦へ進める場合はこの窓口を拡張して最新の閏秒情報を
渡す。未知の将来の閏秒差を固定値で埋め込まない。

## 有名な衛星（2026-09-07追加）

月、イオ、エウロパ、ガニメデ、カリスト、タイタンの6個を描く。
親惑星への接近に合わせて衛星と点線の軌道を表示し、移動中は縮小・減光する。
木星・土星では画面内の中心を少し左へ寄せて衛星を収める。
惑星より遠い衛星を先に、近い衛星を後に描き、掩蔽と手前の通過を表現する。
衛星食・惑星面に落ちる衛星の影・相互重力・共鳴は計算しない。

[JPLの衛星平均軌道要素](https://ssd.jpl.nasa.gov/sats/elem/)から
軌道長半径、離心率、軌道傾斜、昇交点、近点引数、平均近点離角、周期を使用。
月は黄道面、他は各衛星のLaplace面を基準とし、同じモデル日数で進める。
固定楕円で近似し、近点・交点の歳差は省略する。元資料が明記する通り、
平均要素は軌道の一般的形状・方向を示すもので、高精度な位置計算用ではない。
表示される通過時刻・衛星配置を実際の暦として扱わない。

衛星軌道の表示尺度は惑星の太陽周回軌道と別にする。同じ衛星系の中では
kmから画素への単一倍率を用い、木星4衛星の距離比は維持。
月の長半径は54px、カリストは72px、タイタンは62pxへ拡大し、
衛星本体は2～4pxの記号で表示する。惑星の半径と衛星距離の比は実縮尺ではない。

既存の加速度由来の傾きを使い、カメラの方位と仰角に反映する。
追従時定数は0.3秒、保持姿勢への適応は3秒。同じ姿勢で持つと
徐々に巡航へ戻る。センサーがない場合は自動航行のみ継続する。
アプリから戻った際の大きな時間差はカメラへ一括適用しない。

## 描画

main/solar_sail.c に分離。最大1536個の線・円の命令を静的領域に準備し、
240×8画素の既存ストリップへ描く。全画面バッファや毎フレームの
ヒープ確保は追加しない。背景の行単位塗りつぶしは16バイト整列した
入力を使い、PIEで8画素ずつ保存する。索引ロードは不要。
ホストでは同じ色をスカラーで書く参照経路を使用する。
線のラスタライズはスカラー処理で、PIEによる速度向上率は未測定。
既存の転送用PIEバイトスワップも共通して使用する。
軌道の円周サンプルと球の格子は初回に準備する。軌道変換と惑星位置は
1フレーム1回だけ計算。線は整数化前に画面境界で切り、近接時の
巨大な画面外軌道をストリップごとに走査しない。

## 検証（2026-09-07）

- ESP-IDF v6.0.1 / ESP32-S3 のビルドとFlash容量チェック。
- tools/test_solar_sail.c: ASan/UBSan付きで1,200フレームを検証。
  8惑星の滞在・移動・巡回折り返し、ケプラー方程式の残差、
  近日点・遠日点距離と軌道座標の直交性も確認。
  6衛星の所属、周期後の位置一致、近日点・遠日点の範囲、
  惑星に隠れる場合と手前を横切る場合の画素も検証。
  最大傾き、ストリップ前後の番兵、最終7行の未使用領域、
  全画面描画と8行分割描画の画素一致を確認。
  ケプラー残差の許容値は5e-7 rad。`eccentric()` はfloatで解くので
  1e-10はdoubleを主張することになる。実測の最悪値は水星・-226度の
  2.48e-7で、最広ズームでも1画素の1/1000未満。
- 走査線バッファは `.bss` を離れ `scene_mem`（`docs/hardware-constraints.md`）
  の2段ブロックに移った。core 6,028B（三角関数・空・円盤表）と
  bulk 23,552B（`lines` 1,536本と `band_items`）。
  同テストがブロック再利用を検証する: 解放後と、別owner が
  0x5a で塗り潰した後に同じ姿勢を描き、無傷のブロックで描いた
  画像と全画素一致すること。`lines`/`sky` が NULL のときは
  空だけ・単色だけを描き、参照しないことも確認。
  1,200フレームの巡回で `count` の最大は1,273/1,536、
  帯インデックスは4,096を一度も超えない（実測）。
- ホスト描画の画像を目視確認。
- tools/test_solar_time.c: 未同期、UTC変換、2000年の閏日、2038年越え、
  2050年境界、取得失敗、不正時刻、1秒刻み、アプリ復帰相当の時間差、
  時計の再補正、デモ復帰、巡回対象と速度の独立性を疑似時計で検証。
- 実機への書き込み、PIE経路の画素比較、FPS、物理的なIMUの向きは未確認。
