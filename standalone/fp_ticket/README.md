# FP・非FPタスク配置チケット管理部

既存アプリ・デコーダー・FreeRTOS・ビルド設定から独立したC11モジュール。
ファームへの組み込み、タスク作成、コア固定、実機書き込みは行わない。

## 契約

- 2コア、最大16予約。ヒープ確保なし。管理部の計算にもFPを使わない。
- コアごとの上限をppmで指定。1,000,000が1コアの100%。0はそのコアを無効化。
- 要求は処理時間、周期、配置可能コア、FPフラグ、優先度。処理時間/周期を切り上げて予約する。
- `flags=FP_TICKET_USES_FP` はFPタスク、`flags=0` は非FPタスク。
- FPは各コア1予約まで。スリープ中も枠を保持し、空きがなければ `FP_TICKET_FP_BUSY`。
- 追加後の全タスクの予約量/上限が小さいコアを選ぶ。非FPは同率なら非FP数の少ない方、最後はCore 0を優先。
- 優先度は記録するだけ。予約の追い出し、実行順序の制御、待ち行列は持たない。
- 上限不足・予約枠不足は即時に失敗し、管理状態と出力チケットを変更しない。
- 担当コアはチケットの寿命中は変えない。終了後またはタスク作成失敗時に返却する。
- 二重返却、返却済みチケット、別の管理部のチケットを拒否する。

将来の接続順は「予約 → 割当コアの取得 → そのコアに固定してタスク作成」。
既にFPを使い始めたタスクの移動には使わない。既存UIの負荷を登録する際も、
実際の固定コアと一致するマスクで予約する必要がある。

## フラグと保存領域

各ビットが1つの予約スロットに対応する、3本の16ビットマスクを保持する。

| マスク | ビットが1の意味 |
| --- | --- |
| `live_mask` | 登録中 |
| `core1_mask` | Core 1に所属（登録中で0ならCore 0） |
| `fp_mask` | FPタスク |

状態フラグは合計6バイト。コア別FP占有は `live_mask & fp_mask` と所属マスクから算出する。
負荷とタスク数も最大16枠を必要時に集計し、重複したカウンターを持たない。
そのほかにコアのcapacity、定義へのポインター、古いチケットを拒否する32ビットIDを保持する。
IDは再利用せず、使い切ると新規取得を拒否する。常駐管理タスクやヒープ確保は不要。

要求定義はコピーせず参照するため、**返却まで有効かつ変更禁止**。
例えば次のように `static const` にすれば定義をFlashに配置できる。

```c
static const fp_ticket_request_t worker = {
    .runtime_us = 1000, .period_us = 10000,
    .allowed_cores = FP_TICKET_ANY_CORE,
    .flags = FP_TICKET_USES_FP, .priority = 6,
};
```

## 同時実行と寿命

所有タスク1つから操作するか、呼び出し側のmutexで読み取りも含め直列化する。
内部spinlockは設けない。高優先度タスクが低優先度のロック所有者を待って
回り続ける事態を避け、OS依存部分は接続時に決める。

初期化は管理部の寿命の開始時に1回。管理部のコピー、移動、古いチケットが残る状態での
再初期化は禁止。チケットは管理部を指すため、管理部より長生きさせない。

## 判断の限界

申告されたCPU負荷の配置予約であり、CPU時間の強制割当や締切保証ではない。
未登録タスク・割り込み・メモリ帯域・SD待ちは自動測定しない。上限にはそれらの余裕を
残す。平均時間の申告ではピークを取りこぼすため、適切な上限見積もりが必要。
負荷更新や動的な再配置も行わない。
FP各コア1個はこの管理部の配置方針であり、ハードウェアの制約を表すものではない。
3個目のFPタスクはCPUに余裕があっても拒否する。非FPの均等化は申告負荷を優先し、
タスク数だけを同数にする保証はない。管理対象外のFPタスクにはこの制限は適用できない。

## 単独検証

このディレクトリで実行する。既存ファームのビルド設定は不要。

```sh
gcc -std=c11 -O2 -Wall -Wextra -Werror -fsanitize=address,undefined \
  fp_ticket.c test_fp_ticket.c -o /tmp/test-fp-ticket
/tmp/test-fp-ticket
```

テストの6000µs/24000µs等は配置規則を検査する入力例であり、実機の保証値ではない。
